**31 Aug 2026 — codebook v2 got its affordances right, and the user-facing docs turned out to be telling people three untrue things.** The lens work is ordinary and in `git log`. What is worth carrying forward is the shape of what the day's audits found, because all three were invisible to every gate we own.

**`pipx install bristlenose` produced a CLI that could not run.** `serve` is an optional extra, and `_COMMAND_CHECKS` gates **run, analyze and serve** on `serve_deps` — a check returning `CheckStatus.FAIL`, on which `cli.py` raises `typer.Exit(1)`. So the README's primary install line yielded a tool that could only `transcribe`. Homebrew, Snap and Fedora install the extra; pipx and uv were the only channels told not to, and they are what the README leads with and the only route on ARM Linux. `doctor` had been printing the fix all along — nobody reaches doctor before the command they came for fails. Fixed across 13 instructions in README, INSTALL, and the website's install and welcome pages.

**The privacy page said "there is no Bristlenose server".** There is: the feedback form posts to `bristlenose.app/feedback.php`, on by default, and the page's "data leaves the machine **only** in these cases" list omitted it. The payload is genuinely minimal and identifier-free, which is exactly why nobody noticed — the page whose whole job is exhaustiveness had a hole in the list and a denial above it. Its "never in plaintext" credential claim was also wrong for the two shipped channels with no keyring at all (Windows, Snap).

**Two more of the same class, both since fixed:** `how-it-works.md` said "exports use codes by default" when `anonymise` defaults to `false` — a researcher trusting it ships participants' real names; and `the-pipeline.md` said the provider is used at stages 8–11 when `s05b_identify_speakers` also calls it, with up to eight minutes of transcript, **before** PII removal, so `--redact-pii` does not cover that sample.

**The pattern, for whoever runs the next audit.** None of these are code defects. They are documents that were true when written and were never re-read against the thing they describe, and no test in this repo can fail for a false sentence in a Markdown file. The three `user-documentation-review` agents that found them were pointed at code as ground truth and told not to trust the docs — that framing is what did the work, and it is repeatable.

**22 Aug 2026 - a documented invariant about moderator codes said the opposite of what the code does, and the code is lossy.** `bristlenose/stages/CLAUDE.md` claimed `m1` in session 1 and `m1` in session 2 were "independent entries in `people.yaml`".
