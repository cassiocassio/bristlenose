Commentary — the three-part body, and what it replaces

Every popover above is state · cause · action. Today only the middle part exists, and for this family it renders the raw provider string plus Category: api_server — which is computer science, not something a researcher can act on. The state line is new and is the answer to “what am I looking at?”; the action line is new and is the answer to “what is under my control?”.

A3 and A4 deliberately tell you to do nothing. An action line that invents a chore for a transient outage is worse than none — it sends the researcher to check a key that was never wrong. Saying “nothing needs fixing” is the honest action, and it is the reason the mapping is per-category rather than a single generic “try again”.

The relative time is the shipped twin, not a new format: chrome.pipeline.analysedRelative already renders “Analysed 3 minutes ago” in this very row.

Commentary — B3 is the state line’s reason for existing

B1 and B3 look almost identical and mean opposite things. In B1 nothing moved — you still have the 5 you curated. In B3 the run completed, the serve re-imported, and your project is now genuinely 6. Without the state line a researcher cannot tell those apart, and the count in the row is the only clue. Commentary — the four that are decisions, not drawings
  • C2 changes a header. Today an all-files-refused run collapses to unknown and the row reads “Run had failures” — false severity, and a known defect the popover doc already logs. Nothing failed in the machinery; the files were refused. “Nothing new to analyse” is the honest header, and it needs the missing unusable_input entries in pillPrecedence and the pill strings.
  • C3 makes a claim the data supports. “These 20 share one problem” is only safe when the reasons really are identical — which the summary knows. If they differ, it must fall back to the generic action. Worth a rule rather than a hope.
  • C6 drops the state line entirely. With no previous analysis there is nothing to still be showing, and this is exactly the boundary where the status page rightly keeps the whole surface. Same popover, one part fewer.
  • C7 keeps the count without the glyph. If you disagree, the alternative is that a stopped run shows no shortfall either, and the row just reads “Stopped”.

Commentary — what this costs and what it settles

Ten cause lines and ten action lines, in 21 locales. That is the real size of the piece, and it is separable from the two small gates that let the report through at all. The cause column largely exists as pill labels (“Out of credit”, “Provider key issue”, “Rate limited”) — but those are nouns for a one-line row, and the popover has room for a sentence that names the actor (“Claude wouldn’t accept…”) rather than a category.

“Run” is gone throughout, per your steer — analysis is what the researcher thinks is happening, a run is what the computer does. Note the shipped corpus already contradicts itself here: the popover header says Run failed while its own tooltip says Analysis finished with failures. This settles it in the direction the tooltip already chose.

Two rows are load-bearing in an unobvious way. quota and api_server are the only ones whose action is “do nothing”, and they are also the ones a naive mapping would get wrong by inventing a chore. If the action column ever grows a default, the default must be “try again shortly”, never “check your settings”.
