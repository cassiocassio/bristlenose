any-llm on the command line

Built v1 sessions for docs/design-any-llm.md, after the first review pass. Every command, the flags it touches, and each response. Glyphs, colours and today's lines are the shipped CLI's; the any-llm wording is what the built code prints, noted under each frame. Generated by docs/mockups/any-llm-cli-session.py.

3 · configure any-llm — key already in the shell

configure any-llm — Mistral, key from environment
~/research $ export MISTRAL_API_KEY=…
~/research $ bristlenose configure any-llm

Which model? Write it as provider:model, e.g. mistral:mistral-large-latest
Model: mistral:mistral-large-latest
Using the Mistral key from your environment (MISTRAL_API_KEY).
Checking with Mistral (~$0.0001, no transcript content)... ✓ Valid

any-llm is now your provider for analysis (was Claude).
Switch back any time:  bristlenose use claude
Run it with:  bristlenose run <folder>
Commentary
  • Asks one thing: the model. The key was already exported, so nothing is stored (the shell wins, then the store).
  • Checks with the run preflight's own inert request, so green means the run will start (Fable 1, 4). The destination is named: the host when any-llm's provider class carries one, else the provider (Fable 8).
  • Ends with the existing _set_current_provider lines, word for word.

6 · configure any-llm — every way it can say no

configure any-llm — refusals
~/research $ bristlenose configure any-llm
Model: mistral-large-latest
✗ Write the model as provider:model, e.g. mistral:mistral-large-latest

~/research $ bristlenose configure any-llm
Model: mistrall:mistral-large-latest
✗ any-llm doesn't know a provider called "mistrall". Did you mean mistral?
  Providers: https://mozilla-ai.github.io/any-llm/providers/

~/research $ bristlenose configure any-llm
Model: anthropic:claude-sonnet-4-6
✗ Claude is built in. Use:  bristlenose configure claude

~/research $ bristlenose configure any-llm
Model: cohere:command-r-plus
✗ Cohere needs an add-on this install doesn't have.
  Add it:  pipx inject bristlenose "any-llm-sdk[cohere]"
Commentary
  • One offline readiness probe answers all of these: format, known provider, inner SDK present, key present (finding 5). No network, nothing stored.
  • The five built-in providers are refused as inner prefixes and pointed at their own command (finding 15f, proposed).
  • Implementation rule found while drawing this: Rich's auto-highlighter reads anthropic:claude as an IPv6 address and colours it. Every line that prints a model string turns highlighting off.
  • A provider outside the default four names the add-on for this channel. The model string is never echoed back in errors that might contain a pasted key (15c).

9 · use — switching between stored keys

bristlenose use
~/research $ bristlenose use mistral:mistral-large-latest
any-llm is now your provider for analysis (was Claude).
Switch back any time:  bristlenose use claude
Model: mistral:mistral-large-latest (was deepseek:deepseek-chat)

~/research $ bristlenose use deepseek:deepseek-chat
any-llm is now your provider for analysis.
Model: deepseek:deepseek-chat (was mistral:mistral-large-latest)

~/research $ bristlenose use openrouter:x-ai/grok-4
✗ No OpenRouter API key: OPENROUTER_API_KEY isn't set and none is stored.
  Store one:  bristlenose configure any-llm

~/research $ bristlenose use claude
Claude is now your provider for analysis (was any-llm).
Switch back any time:  bristlenose use any-llm
Commentary
  • use provider:model switches to a model whose key is already stored or exported: no network, nothing asked, like use claude. Keys are stored once per provider, so switching never asks for one again.
  • A provider with no key yet changes nothing and names the fix. The first two lines are today's _set_current_provider wording.

13 · run — the provider says no

run — out of credit, bad key, rate limit
~/research $ bristlenose run interviews/

Bristlenose v0.43.0 · any-llm · Apple M2 Max · MLX

Analysis: openrouter:anthropic/claude-sonnet-4.6 via any-llm → openrouter.ai

 ✓ Ingested 4 sessions (4 video)                            0.8s
 ✓ Transcribed 4 sessions (229 segments)                 (cached)
 ✗ Identifying speakers

✗ Your OpenRouter account ran out of credit.
  then run  bristlenose run interviews/  again.

~/research $ bristlenose run interviews/
  ...
✗ Mistral rejected your API key (…x7f).
  Run  bristlenose configure any-llm  to set a new key.

~/research $ bristlenose run interviews/
  ...
✗ Rate-limited by DeepSeek.
  Wait a minute and run  bristlenose run interviews/  again.
Commentary
  • Today's failure banners, word for word, naming the account the researcher has ("Your OpenRouter account…"), never "your any-llm account" (finding 11), with configure any-llm as the key fix.
  • Classified on the inner provider first, so an empty account isn't read as "rate limited" (finding 3). Provider's own words passed through.
  • Rate limits retry with the provider SDK's own defaults first. OpenRouter's and DeepSeek's 402 reads as out of credit through the new provider-agnostic rule.
