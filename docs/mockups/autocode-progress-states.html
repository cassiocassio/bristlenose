Decisions this page surfaces

D1 Whose count does the Mac line show?
The line is native and polls the server (/autocode/jobs), so it counts what the server has saved. It cannot see the window's playback, and with no window open there is no playback at all. So the Mac line counts the server's progress, the window shows the landing, and the two differ by up to one call's worth while a run is live. The lab's “Status line counts” handle shows both.
D2 When does the pop-up say done?
It polls the server and says done when the job does, while the last tags may still be landing for 1 to 2 s. Either it waits for the page's playback (it lives in the same page, so it can), or it says done and the last tags land under it.
D3 Frame 3 on the Mac: Signals takes the line at the total
ProjectSubtitle.swift hands the line to “Picking up Signals…” when the count reaches its total, which is when the Signals build begins. With playback, the window is still landing tags at that moment. Probably fine: the line is about the server's work.
D4 Taking the pop-up away on the Mac leaves frames 5 to 8 with nothing
Today the Mac's AutoCode line exists only while a first apply runs, and disappears when the job stops or fails (ScreenReading.swift keeps only pending or running jobs). The failure is told by the web pop-up, which is not hidden inside the app. Removing the pop-up on the Mac, as asked, needs S1 to S3 first, or a failed run becomes invisible.
D5 Frames 7 and 8: the pop-up ends with two full stops
activity.failed is “{{label}} failed: {{error}}.” and every codebook.autocodeFailure.* sentence already ends with a full stop, so the chip reads “…out of credit..”. Drawn here as it renders. A fix, separate from this design.
