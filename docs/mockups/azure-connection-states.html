Connecting an Azure deployment

What we learned on a real Foundry resource, who holds what when they try to connect, the checks Bristlenose would run, and what the Mac Settings pane and the CLI would say in each state. Built to invent as little as possible: the pane keeps its fields, its status row and its message slot. Each failure has two layers that differ in kind: our interpretation (a sentence of about 20 words, in the researcher’s language) and, behind a Details button that opens the app’s existing popover, Azure’s own raw answer, verbatim, for whoever runs the resource.

Artefact: real pixels in a clean frame. Tags on a frame say whether a sentence is shipped (a live locale key), new (proposed) or unverified (we have not seen Azure say it). Commentary: hatched, not the product.

1 · What we found (the short version)

Commentary
Gathered 12 Nov 2026 on a real, throwaway Foundry resource. Full list with sources, and what is still unverified, is in the design doc §2.
  • Can: one key works on both the openai.azure.com and services.ai.azure.com hosts; GET /openai/v1/models checks the key and endpoint for free (200 / 401); a missing deployment is a clean 404 DeploymentNotFound; the reply names the real model; the classic route works on both hosts for a non-reasoning deployment.
  • Can’t: a key cannot list deployments, so the researcher must supply the deployment name; the portal’s “Endpoint” is a long …/openai/v1/responses URL that today’s client turns into a broken request; a bad key is a 401 (code “401”).
  • Settled since: the run’s request shape (temperature 0.1 + strict structured output) returned 200 on both hosts for a non-reasoning deployment; the response headers and Azure’s own error wording were read. Found by the second probe: the run’s output cap (64000, never clamped for an Azure deployment name) was rejected with a 400 that names the model’s ceiling (32768), so a gpt-4.1-mini deployment failed; fixed in the Python client on 12 Nov (9dc0a4578), and in the Mac app once the sidecar is rebuilt; the 401 body is Azure’s “invalid subscription key or wrong API endpoint”. Not yet seen: a reasoning deployment’s refusals (waiting on quota); what a resource with key-based authentication off says; gateways.

4 · The connection finder: the checks Bristlenose runs

Commentary
One module in Python, used by the run, its preflight, doctor, configure azure; the Mac’s Settings check mirrors steps 0–2 natively (it runs before any sidecar exists) and is held to the Python by a shared contract fixture. Open (D13): the profile is meant to live in memory for the process, but the preflight result is cached for 24 hours and the serve-mode assistants never run the preflight, so “every run re-probes” is not yet true.
0

Read what was pasted no network

https check, reduce to the host, lift a deployment name and API version if the URL carried them.

on to 1endpoint missing (shipped, orange)not https (shipped)
1

Key and endpoint free

GET <host>/openai/v1/models with the key; redirects off; one attempt. Unbilled. Observed: 200 for a good key, 401 for a bad one, on both hosts.

200 → on to 2401 → key not accepted (S1)403 → shipped “HTTP 403” sentence + raw record, never S1 (until U3)404 → not a verdict: on to 2offline · timed out · 429 · 5xxhost not found → S6
2

The deployment one small billed call, as today

Only if a deployment name is present. Send the run’s real request (strict structured output and the real output cap, 64000: never clamped for a deployment name, observed to be rejected, and now retried once at the ceiling Azure names) on the classic route, redirects off, one attempt; read the model from the reply. If the shape is refused: a 400 about max_tokens or temperature → retry once with max_completion_tokens and no temperature; a route or api-version refusal → retry once on /openai/v1.

200 → connected404 DeploymentNotFound → no such deployment400 on the schema → can’t return structured results429 · 5xx · anything else → shipped sentences
3

Hold the profile memory only

Host, route, token parameter, whether temperature is sent, the model reported. The run’s client should read it so the check and the run cannot disagree; see D13 for where that holds today and where it does not.

Commentary
Why step 1 matters: when step 2 returns 404 we already know the key and endpoint are right, so the message can say so. Today one 404 covers the endpoint, the deployment and the API version, so the shipped sentence has to hedge.

5 · Mac · Settings ▸ LLM Provider ▸ Azure

Drawn at the real size: the window is 660pt wide (a 260pt provider list, a hairline, a 400pt detail pane), the cards are about 359pt, and the type is the shipped styles (table below). The red light comes first and is enough for many people; the sentence under it is our interpretation. For whoever runs the resource, a small Details button on the status line opens the app’s existing diagnostic popover (360pt wide, 320pt ceiling, scrolling inside, the header never scrolling) holding Azure’s raw answer: the request line, the HTTP status, the response body exactly as Azure sent it, and the identifying headers. The copy button lives in the popover’s header. The Settings pane gains nothing in height beyond the sentence, so a long record can never push the window (which never scrolls) off a small screen.

7 · What an administrator reads in the raw record

So a screenshot or a pasted line can be answered without a call.

They readThey check (our understanding of Azure; to confirm against U3)
401 or 403Keys and Endpoint: was Key 1 regenerated? Is key access turned off for the resource? Is a network rule blocking the caller?
404 DeploymentNotFoundFoundry ▸ Models ▸ Deployments: does that exact name exist, and was it created in the last few minutes?
400 naming a parameter or response_formatThe deployment’s model family: a newer model refuses max_tokens and temperature; an older one can’t return structured outputs.
429Quota: tokens-per-minute and requests-per-minute on that deployment; the Quota page for the region.
No answer, timed out, host not foundInbound networking (firewall, private endpoint) and whether the host name is right.
Commentary
The record carries the request line (host, path, api-version, the deployment name as typed), the HTTP status, the response body verbatim, an allowlist of response headers (apim-request-id, x-request-id when present, x-ms-region), and our UTC time and version. It never carries request headers, the key, or any part of it, and it passes through the log redactor.

9 · What to ask your IT department (draft, for the website docs)

Draft copy · not for the app
Ask for four things: the endpoint of the Azure resource (in Microsoft Foundry); the name of a deployment of a chat model that supports structured outputs; a key for the resource (say so if your organisation turns key-based authentication off); and enough quota for several interviews at once. Where your data is processed is set by the deployment type (Global Standard, Data Zone Standard or Standard); that is your administrator’s setting, and Bristlenose cannot see it.
