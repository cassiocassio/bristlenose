Codebook browse card — author and title weight

Framed panes are the product at shipped CSS (Inter, browser scale). The hatched block below is commentary. Strings come from the codebook YAMLs and the shipped en keys; nothing in a frame is invented.

Commentary

What changes. The card's author takes the sidebar's and the page's treatment, emphasis weight (490) in body ink, so a name reads as a name on all three surfaces (D19 named three sites; the card was the one left muted). Because the author now carries 490, the title has to step up or the two lines read as equals: A uses the existing semibold token (600), B uses strong (700), the page title's weight at a smaller size.

What does not change. "Available by default" and "On by default" keep the muted, normal-weight system treatment (D23): only a person gets the author's weight. Sizes, spacing, the description, the footrow and the switched-off knock-back are untouched.

The code change would be two declarations in codebook-v2.css, scoped to .v2-card-grid so the v1 rule in codebook-panel.css (still used by the quotes-lens picker cards, if any remain) is untouched. The .prov-system rule already exists and wins on the existing cascade once the new author rule is written with the same specificity.

The Install / Uninstall button. Off-system, by size only. Every .bn-btn sets its label at --bn-text-label (13px, macOS body), including the codebook page's own Install button. .picker-card-toggle, a v1 rule in codebook-panel.css, drops the card's button to --bn-text-caption (12px), and the browse card is now its only user. Its weight, 400, is not a deviation: neither .bn-btn nor body sets one, so every button in the app renders at the regular weight, as a macOS push button does. Both proposal columns put the size back; the fix is deleting that one declaration.

To check on the Mac. The app renders SF Pro at the desktop scale, where 600 and 700 sit further apart than in Inter. Worth a look in the app before choosing.
