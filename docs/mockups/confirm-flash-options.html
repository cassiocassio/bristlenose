Siblings of the pattern, already shipped and tokenised: the arrival flash (atoms/arrival.css: --bn-arrival-colour/-duration/-easing, a from-only keyframe, markArrived(el) writing data-arrived, cleared on animationend with a getAnimations() guard, pinned by tests/test_arrival_css.py) and the lens handover dim (bn-handover 240 ms, with HANDOVER_MS in useLensRead.ts kept equal to the CSS by comment). Commentary

Same pixels, different plumbing. The brightness pulse is unchanged in B: 1.35 → 1 over 400 ms. What differs is that the hook owns the timer and its length comes from one constant pinned equal to the CSS token (the HANDOVER_MS pattern), so the strips line up; today the class outlives the animation by 100 ms, harmless until someone lengthens the CSS past 500 ms and the flash is cut short with no test to say so.

“Add twice” is the behavioural difference. Today the second press is swallowed (Set semantics). B restarts: the hook bumps a nonce per key and the badge takes key={nonce}, so React remounts the 20-byte span and the animation starts clean. This sidesteps the remove-reflow-set trap the arrival flash hit on 17 Oct (animationcancel of the old run landing on the new listener), because there is no listener: the hook’s timer is the clock.

Renders. Both columns re-render the group twice per flash (state in, state out), and flashingTags is a new Set each time, so every card in the group renders with it. The hook does not fix that; it could (a per-key subscription, or the arrival-style DOM mark with zero renders). See the open call in the recommendation.

Reduce Motion: kept, in both columns. A brightness fade moves nothing; this is the arrival decision applied, not a new one. Light-appearance check owed: brightness 1.35 on a 94 %-lightness pastel tint has little headroom (the shimmer needed 20 % on the web chip against 5 % native for the same reason). Measure before fixing the peak token; the token exists so the fix is one line.

B Class plus hook

siblings: A, and useLensRead.ts (HANDOVER_MS kept equal to the CSS) for the hook’s shape
Code shape
// hooks/useConfirmFlash.ts
/** Equal to --bn-confirm-duration; tests/test_confirm_css.py pins both. */
export const CONFIRM_MS = 400;

export function useConfirmFlash() {
  const [nonces, setNonces] = useState<ReadonlyMap<string, number>>(EMPTY);
  const timers = useRef(new Map<string, number>());
  const flash = useCallback((key: string) => {
    setNonces((p) => new Map(p).set(key, (p.get(key) ?? 0) + 1));
    clearTimeout(timers.current.get(key));
    timers.current.set(key, window.setTimeout(() =>
      setNonces((p) => { const n = new Map(p); n.delete(key); return n; }), CONFIRM_MS));
  }, []);
  useEffect(() => () => timers.current.forEach(clearTimeout), []);
  return { flash, nonce: (key: string) => nonces.get(key) };
}

Consequences
  • M build — A, plus one hook with its own test, four writer blocks collapsed, the QuoteCard/TagRow prop shape changed (Set → nonce lookup, or keep the Set and derive it: the smaller diff). FocusContext’s registry stays: it is the channel, not the flash.
  • Fixes the drift (one constant, pinned), the swallowed second press (nonce restart), and the leaked timers on unmount (today none are cleared).
  • Test surface: jsdom runs no animations, so the hook test pins the Map and the timer with fake timers; the restart is proven once in Playwright. Four QuoteCard tests that pass flashingTags={new Set()} change only if the prop shape does.
  • Rules out: nothing. Converting later to a DOM-mark implementation changes the hook’s body, not its callers.

Recommendation: B, done in two commits, with the Set kept as the prop

Commit 1 is A: atoms/confirm.css beside arrival.css, three tokens, the rename, the frozen-only comment on badge-bulk-flash, a CSS test in the arrival test’s shape, and the Swift regeneration. It is a small, safe change on its own. Commit 2 is the hook: useConfirmFlash() with CONFIRM_MS pinned to the token, replacing the four writer blocks; QuoteCard keeps receiving a Set (derived from the hook’s map) so its four test files do not move; the restart lands in QuoteCard as a key on the badge. This follows the live React-class family (handover) rather than inventing a third mechanism, and it is a refactor of a shipped cue, which the beta line allows.

Not C. It ties a one-afternoon refactor to a decision Q7 recommends against, and splits the token naming. Not D. The row is tagged [trust]; a cue that skips the second press and has three durations is the kind of small unreliability that tag is about.

Owner calls the mockup could not settle: (1) keyed React state (the handover family; two group renders per flash, as today) or a DOM mark like markArrived (the arrival family; zero renders, but a querySelector for the badge and the animation-restart guard): the hook’s callers are the same either way; (2) should the hook live in FocusContext, next to the registry it feeds, or stand alone in hooks/; (3) whether the peak brightness needs a per-appearance value for light pastel tints: measure first.
