Sidebar footer: version and Send Feedback

Mac app only. At the bottom of the sidebar: the app version as small plain text on the left, and a small borderless bug button on the right that opens Send Feedback in this window. The version is shown to everyone while we're in alpha. Rev 2, after the 3 Oct review: plain text instead of a capsule, the list slides under a soft edge, the tooltip has no ellipsis.

Artefact: what would ship Commentary: why orange in a frame's chrome bar = NEW copy, not a shipped key
Stage word (not part of the artefact):

1 · The footer: macOS 26 and later (soft edge), and macOS 15

What it's made of. The version is plain Text: .caption2 (10 pt), .monospacedDigit(), .secondary, no background. That's the usual “Version x” footer, and it sits on the sidebar's own vibrancy, so Reduce Transparency and Increase Contrast take care of themselves. The bug is SF Symbol ladybug (there's no plain bug) in a .borderless button, .secondary, with no bezel at rest. The glyph stays small; only its invisible click area is 22 × 22.

The list slides under. On macOS 26 and later the footer is a .safeAreaBar, which gives the system's soft scroll edge: rows fade and blur as they pass beneath it (the CSS blur here only approximates it). macOS 15 has no soft edge, so text would run behind text; there the footer stacks below the list instead (the macOS 15 frames). No rule above it on either.

2 · Narrowest sidebar (200 pt, columnMin)

At 200 pt the version text (~62 pt) and the button (22 pt) leave plenty of air, so nothing truncates. A long version string (0.32.10 alpha) still fits. When the sidebar is hidden, the footer goes with it; Help ▸ Send Feedback… is still there.

3 · Button states

Hover shows the borderless hover fill (macOS 26 only; 15 shows the tooltip alone) and the tooltip “Send Feedback”, a new key without the menu item's ellipsis, also used as the VoiceOver label. Clicking opens the shipped native FeedbackSheet in this window only: the button sets this window's sheet state directly, not the app-wide broadcast the menu uses today. It works with no project selected, since the sheet falls back to its serve-free config. Focus ring only with Full Keyboard Access on.

4 · Debug builds: two versions on screen

In a Debug build with Show Diagnostics on, the existing build-info capsule still sits bottom-right of the detail pane. The version then appears twice, which is fine: the capsule carries branch, SHA and sidecar for QA screenshots; the footer is the one line a tester can read out. Not proposed: trimming the version out of the Debug capsule. It's Debug-only and its format is documented in BuildInfo.swift.

5 · At 2×: the Debug capsule (unchanged) and the footer

Rev 1 copied the capsule. Rev 2 drops it: on a sidebar the material sat on top of the sidebar's own material, it read as one of the app's clickable status pills, and Reduce Transparency turned it into a solid pale blob. Drawn at doubled sizes, so it shows shape and spacing, not antialiasing.
