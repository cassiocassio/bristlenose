2 · The StatePane molecule — three ways to have one, including not

The catalogue (§"The collapse map") asked for one component instantiated ten times. SwiftUI shipped that component in 2023: ContentUnavailableView is the centred {icon, headline, body, 0–1 action} molecule, and every pane already uses it. So the question at HEAD is narrower: is a Bristlenose wrapper over the stock primitive worth having, and if so what does it buy that a test could not.

The artefact is identical across the three options by construction — same pixels, different plumbing — so one frame stands for all three. The options differ in the right-hand column of the comparison table, not in the picture.

the pane every option draws (shipped: the failed cover, quota category)

A · No wrapper — the primitive is the molecule shipped

Nearest sibling: every other ContentUnavailableView in the app (BootView, CloudImportWindow ×9, DoctorReportView).

Keep the 20 call sites. The variation table the catalogue wanted already exists as data: DetailPaneKind (which pane), RunCover (which cover), FailureRemedy.of (which button). Add one cheap test, not a type: every desktop.chrome.* and desktop.boot.* headline key ends without a full stop and is not Title Case, so decision 3 cannot drift by accident.

Build cost
S — one pytest over en/desktop.json; no Swift change.
Layers touched
tests/ only.
Risks
A new pane written in a hurry copies a site and forgets a convention the test does not cover (the ring-in-icon-slot idiom, the Show details disclosure). Two idioms are hand-written twice today and would be three times.
Rules out
Nothing. B or C can be added later; A is their baseline.

B · A thin StatePane over the primitive, driven by a spec

Nearest sibling: DetailPaneKind.resolve itself — a view's decision lifted into a testable helper (house convention, desktop/CLAUDE.md § Conventions).
struct StatePaneSpec: Equatable {
    let symbol: String?          // nil = the run ring takes the slot
    let headlineKey: String
    let bodyKey: String?
    let actions: [StatePaneAction]  // .resume, .retry, .setUpProvider, .locate, .showDetails
}
extension DetailPaneKind.RunCover { var spec: StatePaneSpec { … } }
struct StatePane: View { let spec: StatePaneSpec … ContentUnavailableView { … } }

The sentence the native-primitives rule asks for: the system primitive is ContentUnavailableView; we wrap because twenty sites share two idioms it does not have (a live ring in the icon slot, a Show details disclosure), and a spec lets one test assert that every case names keys that exist in all 21 locales.

Build cost
M — ~150 lines of Swift, a StatePaneSpecTests that walks every case, 20 sites rewritten; no new strings.
Layers touched
desktop/ views and tests. Locales untouched.
Risks
A wrapper that has to carry an escape hatch for the startup-refusal pane (two body paragraphs, a default-action button) and the analysing pane (observes per-second progress) is two special cases on day one; if the spec grows a closure it has stopped being data. Rewriting 20 working sites is a regression surface the owner does not see as a feature.
Rules out
Nothing in the product. It does tie future panes to the spec's vocabulary, which is the point and the cost.

Commentary — §2, is this Bristlenosey?

Kind: a native empty/status pane, one of 20. Sibling: ContentUnavailableView everywhere, with the decision in a helper (DetailPaneKind). A follows the sibling exactly. B departs with a written sentence; it is the catalogue's own proposal, but written before the panes were built on the stock primitive, when there were still three idioms to unify (two VStack hand-layouts and a Jinja page). C follows the Seams mechanism and addresses the one guarantee nothing gives today. None invents.

The dispatch-table lesson in CLAUDE.md (§ Gate policy: "any name-to-runner table needs a structural test that every listed name resolves") is the strongest argument for either B or C over A: today nothing asserts that every RunCover case has a pane with keys in all 21 locales — check-locales.py proves the keys exist, not that the switch reaches them.

Commentary — §3

What was checked. The body line "The report opens as soon as the first interview is readable." is a promise; the original mockup flagged it as needing a check on the cover path. At HEAD the Mac side hands over through shoalTakesPane only for the shoal; on the cover path the serve decides: page_for(…, sessions_imported:) returns the SPA once ProgressiveImport.follow has imported a session, and RunCover.analysing only draws over a .statusPage document. So the promise holds on both paths in code; it has not been watched on a real run with the animation preference off, and that is a human QA item, not a design one.

Why 3a-B is the Bristlenosey pick. The stopped and stranded panes put their verb (Resume Analysis) in the actions slot; the analysing pane is the same molecule in the same family and is the one state where the researcher might want the opposite verb. "Not needy UX" cuts the other way here: a single plain button that names a real act is not a retry loop or a nag. C alone fails discoverability; C with B costs little and honours "same element, same action" for anyone who learned the row's ring.

Why 3b-A. The shoal already yields to the report at the first readable session, and the row never stops narrating. Adding words to a surface whose design rationale is wordlessness re-litigates a settled call for parity's sake; the parity rule (decision 5) is about facts, not quantity.

Recommendation

§2: A now, C when the next wording change touches both surfaces. The molecule the row asked for exists — it is the stock primitive, and the decision table is already data. A wrapper (B) would have been right in June when three idioms needed unifying; today it rewrites twenty working sites to gain a test, and the test is the valuable part. Write the casing test now (S). The guarantee nothing gives today is pane↔browser fact parity; that is a seam, and the house mechanism for a seam is a contract fixture read from both languages (C), not a Swift type. Build C the first time someone changes one of those sentences, so the test is born with a reason.

§3a: B, with C folded in if it costs under an hour. Stop Analysis in the actions slot is the same slot, the same family and an existing string; it is the only pane in the set whose siblings offer the opposite verb and it offers nothing. Hide it while "Stopping…" shows. §3b: A. Leave the shoal wordless; the row narrates, and the pane yields at the first readable session.

§4: A — the icons are no longer placeholders; this is a yes/no. §5: split the one straggler when a locale pass is next open anyway.

Human QA owed regardless of pick: watch one real multi-session run with the shoal preference off and confirm the quiet pane hands over to the Sessions lens at the first readable session (the body line is a promise). Not a mockup question.
