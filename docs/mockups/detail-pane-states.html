Detail pane states — one family, re-applied

Every state the detail pane can show, sorted into five groups by what the researcher can do about it. The Mac draws each one with the stock ContentUnavailableView that eight panes already use: an icon, a headline, one line of body, and at most one action. Where bristlenose serve has a twin, the browser frame shows the shipped status page. Nothing here is a new component. What changes is the words and the icon in each slot. Every changed string is outlined, and the string table in §5 lists them all in one place.

Commentary — the rule this applies
  • Native primitives only, as they are today. The stock ContentUnavailableView, the run's progress on the sidebar row's status line, app-global progress in the toolbar pill, and the shipped status page for the browser. The run ring is the sidebar's own SidebarActivityRing.
  • How the panes are drawn. The pane sizes were measured from a real ContentUnavailableView, rendered through ImageRenderer on this Mac. The icons are the real SF Symbols, rendered from AppKit by experiments/icon-system/render_sf.swift. The status page CSS is templates/status-page.css, inlined verbatim. detail-pane-states.gen.py regenerates those three blocks.
  • What is not drawn. The report itself, the Welcome window, and the popovers, except where a before/after needs the popover beside the pane.

Commentary — §5
  • Count. 16 rows reword an existing key, 2 retire one (the stopped and stranded bodies) and 8 add a new one (two of them share one key, Resume Analysis). Three rows also add a native twin for the Mac pane (the stopped headline, the stranded body, the failed headline), so that is 10 new keys in all, each in 21 locales. The suggested key names (amber) follow their neighbours’ namespaces. They are placeholders for whoever builds this, not part of the decision.
  • Casing. Every proposed Mac headline is in sentence case. That ends the native/server split the June catalogue recorded (“Project Moved or Deleted” beside “Last run failed.”). Buttons stay in Title Case. Decided (Q3): sentence case, no full stop — the HIG’s Writing rule, one style per element type. Proposed headlines also drop the full stop, as ContentUnavailableView titles do on macOS.
  • Interpolated names. “{{name}}” and “{{host}}” are typeset with each locale’s own quotation marks, so the curly quotes are part of the translated string, not code.

6 · Questions for you — answered 24 Oct 2026

Commentary — decisions this mockup needed, with the owner’s answers
  1. Native or unified copy only? Should the Mac take over the failed, stopped and stranded panes natively, as drawn? The alternative keeps the serve’s status page in the pane and only unifies its words with the popover’s.
    Answer: native, as drawn. The Mac draws failed, stopped, stranded and refused with ContentUnavailableView; the browser keeps the status page with the same words.
  2. Brand on the engine-failed pane? Should it keep the app icon, wordmark and tagline (option A), or join the plain family (option B, §2.4)?
    Answer: option B, the plain family. Starting is already bar-only, so no pane keeps the brand block. N08’s buttons are decided elsewhere: docs/design-feedback-native.md § “Feedback and problem reports” (mockup n08-button-set.html).
  3. Casing. Should Mac pane headlines be sentence case, with Title Case kept for buttons only?
    Answer: sentence case, no full stop; buttons Title Case. The HIG’s Writing page asks for one style per element type, used consistently; its Alerts page (fragment → Title Case, sentence → sentence case with a stop) was considered and not taken.
  4. Stopped. Should it show a neutral pane with Analyse, or show the previous report when one exists?
    Answer: the previous report when one exists, the row saying Stopped; the neutral “Analysis stopped” pane with Resume Analysis only when there is no report. This is D4-B for cancelled runs only (docs/design-project-condition.md §6.1); D4 for failed runs is not decided here.
  5. Pane and row wording. May a pane headline differ from the row’s sentence for the same state? For example “6 files to analyse” beside “6 files not analysed”, or “Choose an AI provider…” beside “Provider not set up”.
    Answer: yes — the wording may differ, the fact may not. The row is the status, the pane the instruction; queued and analysing keep the row’s own line.
  6. Naming providers. May the no-provider sentence name the four providers? Each new provider would then mean a copy change in 21 locales.
    Answer: two examples, not the list — “Bristlenose sends the transcripts to an AI provider such as Claude or ChatGPT. Pick one in Settings.” It stays true as providers are added, and with Local.
  7. Multi-select. Should the multi-select pane stay a dead end, as drawn (no action)?
    Answer: a dead end, as drawn. Actions on several projects stay in the sidebar’s context menu and the Project menu.
