Set up Azure OpenAI

A stand-in for set-up-azure.html. The tabs only appear where a command differs by shell.

Connect Azure OpenAI

› macOS app
  1. Open Settings (⌘,) and go to the LLM tab.
  2. Select Azure OpenAI and paste your key into the API Key field.
  3. In the Azure Settings section, fill in the Endpoint, Deployment name, and API version.
› Command line

Set the endpoint and deployment as environment variables, then store the key:

export BRISTLENOSE_AZURE_ENDPOINT=https://my-resource.openai.azure.com/
export BRISTLENOSE_AZURE_DEPLOYMENT=my-deployment-name
bristlenose configure azure
$env:BRISTLENOSE_AZURE_ENDPOINT = "https://my-resource.openai.azure.com/"
$env:BRISTLENOSE_AZURE_DEPLOYMENT = "my-deployment-name"
bristlenose configure azure

The optional BRISTLENOSE_AZURE_API_VERSION defaults to 2024-10-21.

In PowerShell a $env: variable lasts for that window only. To keep it, put the lines in a .env file.

When Windows needs more than a paragraph

Same page, other pattern. Here the Windows steps differ enough (a different installer, a restart, a persistence step) that tabs would hide too much. The fork gains a third section, and the Unix one is renamed macOS / Linux. Sample copy, not final wording.

› macOS app

Open Settings (⌘,), go to the LLM tab and choose Local (Ollama). The app offers to install Ollama if it is missing.

› macOS / Linux

Install Ollama, pull a model, and point Bristlenose at it:

brew install ollama
ollama pull gemma4:e4b
export BRISTLENOSE_LLM_PROVIDER=local
export BRISTLENOSE_LOCAL_MODEL=gemma4:e4b

On Linux, use Ollama's install script in place of brew.

› Windows PowerShell
  1. Install Ollama, then open a new PowerShell window. The installer changes your PATH, and a window that was already open won't see it. 
    winget install Ollama.Ollama
  2. Check that the Ollama icon is in the system tray. It runs the server in the background, so there is nothing to start by hand.
  3. Pull a model: 
    ollama pull gemma4:e4b
  4. Point Bristlenose at it. setx keeps the values for every new window, unlike $env:, which lasts for one: 
    setx BRISTLENOSE_LLM_PROVIDER local
setx BRISTLENOSE_LOCAL_MODEL gemma4:e4b
    Close and reopen PowerShell before running bristlenose.

If you would rather not touch environment variables, put the same two lines in a .env file in your project folder instead.
