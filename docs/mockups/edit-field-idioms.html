Inline edit fields

Four different answers to “is this field live?” ship on one screen today, and two surfaces answer it with nothing at all. The fix is not a fourth invention — it is one signal whose fill inverts with the ground it sits on, plus one named exemption. Columns two and three are live CSS, not screenshots: what you see is what the declarations beneath them do.

Exempt — quote crop and trim

Not “edit this text” but “move this boundary”. Custom by design, one signal with the burnt-amber brackets. Keeps its yellow, now honestly named --bn-colour-crop-bg. Do not restyle it to match, and do not borrow that yellow.

Untouched, deliberately. The verb is different — you are moving a boundary, not retyping a string — and the yellow was designed to read as a single signal with the brackets. A different verb is allowed a different look.

Not one declaration changed. What changed is the name: --bn-colour-editing-bg is now --bn-colour-crop-bg, because a token named for a state it must not be used in is how three other surfaces came to borrow it in the first place. Same hex, same rules, same pixels.

A different animal, and the distinction is worth stating so nobody “aligns” these next. A real <input> has a box at rest: it is visibly a field before you touch it, so focus only needs to promote the resting border to accent. An inline edit has no box at rest — it is prose until you click it — so focus has to conjure the field, which is why it needs a fill as well as an edge.

Rule of thumb: if the reader can see it is a field before interacting, use the resting-border pattern. If they cannot, use the --bn-field-edit-* set.

What this replaces. Before: five treatments for one state — yellow (static byproduct only), accent outline plus tint (speaker names), accent border plus page background (codes), a 12%-alpha ring on grey (code rename, since fixed), and nothing at all (theme headings, theme descriptions, code group titles, code group subtitles). After: two, chosen by the ground, plus one named exemption.

Where the decision lives. bristlenose/theme/tokens.css, the inline-edit block — it carries the rule, the two tokens and the exemption in one comment, so the next person styling a field reads the answer where they look up the radius.

Swept at the same time. The crop token is renamed --bn-colour-crop-bg everywhere it is declared, used or taught — including the ux-critique agent, which was instructing reviewers to demand the old one, and edo-theme-studio.html, which generates palette CSS and would have emitted a dead name. --bn-colour-editing-border is gone from both palettes and the contract; it had no consumers left. molecules/name-edit.css is deleted and dropped from _THEME_FILES — its .name-cell / .name-text / .name-pencil classes were emitted by nothing in the repo, and its one live rule (.unnamed) moved to person-badge.css, scoped to the two classes that actually use it.

Left alone on purpose. The frozen *.theme.css snapshots beside this file are self-contained historical copies taken for other mockups; renaming inside them would edit the past to no benefit. And theme/js/names.js still ships in _JS_FILES querying .name-text and .name-pencil — selectors nothing emits, so the module is inert. It is frozen vanilla (data-integrity fixes only) and its removal is a separate call, with a load-order assertion in tests/test_hidden_quotes.py to update.
