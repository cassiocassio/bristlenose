A run that stopped or failed part-way: what the row says, what the pane offers, and whether a fresh start needs its own verb

artefact — what would ship commentary — why, cost, risk

The question

A researcher drops eight interviews, presses Analyse, and stops it (or it fails) after three. The folder holds the recordings and a partial bristlenose-output/, and there may be no report yet. The row’s original worry was that this looked like an empty study. The 100days row listed four remainders: (a) what the row says when the database cannot tell what has been ingested, (b) an honest empty state (“N interviews ready · Analyse”), (c) a separate Clean / Start Fresh, (d) the stopped state’s Resume and Re-analyse… CTAs. Checked at HEAD on 7 Nov 2026, most of it is built. What follows separates the done from the open and mocks the open.

Commentary
  • S1 says “Stopped” and nothing else, in the row, the tooltip and the pane. The database cannot count, so the title line has no number — “unknown is not a licence to shout” holds, and it is right. What the researcher cannot see is that eight recordings are there and all eight are still to do.
  • S2 knows the answer and spreads it over two places: the title’s 3 (sessions in the DB) and a hover that says “3 interviews · 5 waiting”. The row line itself says only “Stopped”. If a report existed before the stop, the pane shows that report instead (decision 4), and the count is then on the dashboard.
  • The pane names the act and not the extent. “Analysis stopped” + Resume Analysis is correct and plain; it is also the same sentence for S1 and S2, and the one question a researcher brings to a stopped study is “how much is left?”.
  • Glyph: none, by the 18 Jun rule — they stopped it, so it is not news. Door: none; the files popover opens only from a delta glyph, and there is none here. Both stay as they are in every option below.

M .stopped and .partial gain done/total from the manifest (Swift: parseManifest, EventLogReader.deriveState, SubtitleVariant, SidebarSubtitleText, tests); Python writes nothing new if the per-session map already carries stage status (to confirm against manifest.py). No new locale key.

  • Siblings: .completedPartial says “6 of 8 sessions analysed” on the row (decision #139) — a fell-short outcome already carries its count on the line. The cloud batch says “3 of 4” because “a count is the question a closed window leaves”. The running ladder shows “3 of 8” the second before Stop. A2 follows all three; the continuity is the point: the line after Stop is the line before it, minus the verb.
  • S1 under A2: “0 of 8” answers the (a) question directly — the database cannot count, but the manifest can, and it is the manifest the stop was written to. If even the manifest cannot say (no manifest, events log only), the row falls back to bare “Stopped”: unknown still is not a licence to shout.

The row uses the run’s total; the pane (below) can say “and 1 new file” from newFiles once the DB has a baseline. Keep the two numbers apart as the code already does.

(c) · a fresh start where Re-analyse… is hidden

Does S1 need a way to throw the partial output away?

Re-analyse… is the fresh start and it is gated on sessionCount > 0. In S1 nothing reached the database, so the context menu offers Analyse (resume) and nothing destructive. Three positions:

Commentary

S · 0 Resume reuses the three transcriptions and pays for five. A fresh start would pay for eight and keep nothing the researcher made, because nothing was made. There is no loss to protect and no saving to offer. The one case it does not cover is a cache that is wrong rather than partial — and a damaged manifest already routes to Analyse, which sets it aside and rebuilds (decision #18).

Recommendation

(a)/(b): A2 + A3. A stopped or partial row keeps the count the ladder was showing when it stopped — “Stopped · 3 of 8”, from the manifest, in the shipped {{complete}} of {{total}} form — falling back to bare “Stopped” only when even the manifest cannot say. The stopped and interrupted panes add one line, “3 of 8 interviews analysed”, under their headline. No glyph, no popover, no new row state. This answers the (a) question as reframed: when the database cannot count, the row says what the manifest knows, and stays silent when nothing does.

Why. The completedPartial row already puts its count on the line; the running ladder already shows this exact pair; the cloud batch’s rationale (“a count is the question a closed window leaves”) is this situation to the letter. It is continuity, not a new pattern. The one thing a researcher wants from a stopped study on Wednesday is how much is left, and today that is in a hover on S2 and nowhere on S1.

(c): C1 — no new verb, no gate change. Resume is strictly cheaper than a fresh start on S1 and loses nothing, because nothing was made. The damaged-cache case already routes to Analyse. If a real corrupt-but-parseable cache ever shows up in a trial run, C2 is a one-line gate change with the sheet behaving as decision #1 already specifies; it does not need to be built ahead of the case.

What the owner still has to settle

  • The denominator. “of 8” is the run’s session total from the manifest/events, not the folder’s file count. If a file is added overnight the row still says “3 of 8” until the next run; the tooltip’s “M waiting” (S2 only) is where the new file shows. Accept, or should the row say “3 of 8 · +1” — which the status-roll plan would then also have to carry?
  • Does “Transcribed · 8 of 8” earn its count? A transcribe-only run that finished has done everything it set out to; the count is confirmation, not news. Recommend the count only on .stopped and on .partial(transcribeOnly: false), not on Transcribed.
  • Register on the pane: “interviews” (the pane’s word) or “sessions” (the row’s)? Recommend interviews on the pane, sessions on the row, as shipped.
  • Is there a known wrong-cache case? If a trial run has produced a partial output that Analyse cannot resume from and the manifest is not damaged, C2 is justified today; otherwise C1 stands.
