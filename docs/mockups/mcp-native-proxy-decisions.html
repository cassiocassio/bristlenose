Native proxy — what the decisions look like

The user-facing consequences of plan v2's decisions D1–D9 (docs/design-mcp-native-proxy.md §6.9), drawn at the shipped 660pt Settings width, so they can be judged on UX as well as engineering grounds. 29 Sep 2026. Strings are the shipped en keys unless a commentary block lists them as new.

Bristlenose, as it would ship another app (ChatGPT, Claude): a schematic from our screenshots, not their pixels commentary: not the product

Engineering read of D1–D9, before the pictures. Five decisions I'd take as written, two that need an amendment, and one new risk the plan doesn't name yet.

#VerdictWhy, and what it costs the user
D1TakeFresh ids cost nothing, and the user never sees them. The number of signer classes is a P0.2 measurement, not a design choice: the local Apple Distribution build and the Apple-re-signed TestFlight/App Store build can share an id and still hang the helper (§6.6). In practice only the maintainer's Mac holds both, so the hazard is ours, not users'.
D2TakeA few seconds of swiftc per Release build buys "the helper is always as fresh as the host". A Debug build has no native path, so a Cmd+R build can't exercise it. That makes the manual P6 pass on a Release build a requirement, not a nicety.
D3TakeOne gate over both copies is the right shape, with file-then-grep for the SIGPIPE trap. Invisible to users.
D4Take, with one questionFail closed is right. But ask the server too: when Agent Access goes off, does serve refuse that project's MCP calls whatever the handshake says? If it does, a stale group copy only points a proxy at a door that's shut. If it doesn't, D4 is the only guard, and the unlink must be verified. Not checked yet.
D5TakeWith no new diagnostics, the proxy's sentences have to carry the recovery on their own. Section 6 shows them. The native "can't reach" sentence is vaguer than today's Files & Folders one ("install again, or check for an update"), because it covers three different build defects, each of which D3 should stop from shipping.
D6TakeOne commit, one release, one tester, and rollback is a revert. The cost is section 7: in that release, every existing Claude user needs one reinstall.
D7Take; the refusal needs copyA marketplace inside the bundle is the only readable place. It is a .dmg-only case: the App Store never translocates. The refusal is drawn in state 2.6.
D8TakePer-host state keyed by our own label keeps "know the protocol, never the client" intact. It inherits today's honest blind spot: until the first question arrives, the button still says Install, because we can’t see ChatGPT’s or Claude’s state. Section 2 shows it.
D9TakeExternal TestFlight before the store costs one review cycle, and it is the only way a human reviewer sees the helper before the public does.
newAdd to P0.4Where does the runtime .mcpb live when Claude opens it? If it's written to our temporary directory, which sits inside our sandbox container, then Claude reading it is exactly the cross-team container read macOS 27 denies. The Install dialog could then fail in Claude with no message from us. P0.4 must test the real path, not an unzip we control. Fallbacks, in order: a location Claude can read (the bundle can't hold it, because Apple re-signs the helper after the zip is made), or an explicit save. Inferred, not measured.

Consequences the pictures show.

  • 2.1 and 2.2 both say Install, even just after a successful install. That's today's rule on the Claude tab (.unknown and .matching map to Install) and D8 keeps it: we never say "Installed", because we can't see ChatGPT. The "it worked" signals are the shipped ones, and they arrive with the first question: the sidebar antenna radiates, the register's Last asked turns to Just now, and the row's subtitle says an agent asked recently (2.2). Benchmarked in section 8.
  • 2.3 depends on the plugin version. The version carries the build number, so ChatGPT caches the new copy under a new folder. Whether ChatGPT then offers "Update" by itself, or needs uninstall-then-install, is P0.5 (section 5).
  • 2.4 and 2.5 reuse the Claude tab's Link-instead-of-button pattern, so a dead button never produces the system's "no application" dialog. 2.5 can only be detected as "the app is there but no codex:// handler is registered". A ChatGPT that has the handler but ignores marketplacePath isn't detectable (F23), so a minimum version check goes on top.
  • 2.6 is .dmg-only. The button is disabled rather than hidden, so the reason sits next to the thing it blocks. The copy deliberately doesn't say "translocation".
  • 2.7: the TOML route survives for Codex CLI and IDE users. It is the one path that still re-copies after every restart, and the copy says so.

New strings (would go into 21 locales): chatgptHint, installPlugin / reinstallPlugin / updatePlugin, pluginBuild, downloadChatGPT, updateChatGPT, moveToApplications, connectByHand, and a shorter chatgptCodexHow for the TOML route. The ellipsis stays on "Install Plugin…" because the command finishes in another app (F9).

The antenna already answers "is it working?" (right-hand frame, drawn loosely: the real one is the SF Symbol antenna.radiowaves.left.and.right, animated through its three variable-value frames). It is solid for an exposed project, radiates while an agent reads it, and taps twice when the agent has finished. That beats Xcode's alert on two counts: it's per project, and it says when the agent has finished. Nothing in this plan should duplicate it, so the "is asking now" subtitle I first drew here is withdrawn.

What's left is narrow. The antenna can't show "connected" before the first question or which host asked, and the install row still says Install after a successful install. Two small changes close it, both facts about our own endpoint, not about the client:

  • At MCP initialize, the helper checks in once (/api/health, carrying its host label and build). The row can then say "ChatGPT connected today at 14:02" the moment "Try now" opens a thread. The helper writes nothing, so this isn't D5's rejected breadcrumb.
  • Serve keeps the last check-in per host (D8 already keys by host). After that, .matching becomes a bordered "Reinstall Plugin…", and at rest the pane has no filled button.

Worth it? It's optional. For a researcher, the first question plus the antenna already proves it works. The check-in mostly fixes the Settings row, which would otherwise read as if the install hadn't taken.

The other shortfalls, and what I'd do. ChatGPT Work vs Chat in the docs: when the help page (work-list item 2) ships, give it ACE's treatment, with a screenshot of the Chat | Work toggle and one sentence on why Chat can't reach a local app. Per-item exclusion (DEVONthink): this is a product question, not part of this plan. A per-session "exclude from agents" would be the Bristlenose version. Park it.
