Send to Miro: Miro app and developer token as tabs

artefact = the framed dialogs, real Bristlenose CSS (tokens, palette, atoms/modal.css inlined) · new = proposed words or element, not yet built · commentary = the hatched block below

Commentary · not the product

The shape (owner, 8 Nov 2026). Send to Miro stays the one Miro entry point and splits into two tabs. Miro app (Miro's own word for it: an app you add to a team) is the default and needs no setup: three plain lines that are also the explanation (no step numbers: a dialog isn't a numbered list), Copy board data as the primary button (fewer clicks: no file to find) and Download board file as the option, offered as Either … or …. The settings come first, above the rule, so they are chosen before anything leaves Bristlenose; the instructions and buttons follow. Developer access token is today's dialog, unchanged, under a name that tells most people it is not for them. The dialog always opens on Miro app, even for someone connected with a token (owner, 9 Nov 2026: it is the better route); the token tab is one click away.

The Mac form (owner, 9 Nov 2026). The Miro app tab is laid out as Mac settings are: each label ends in a colon and right-aligns on one axis, each control left-aligns in the column beside it, and a full-width rule separates the choices from the steps. Either: and or: stack the two buttons one under the other, the same width, rather than running them through a sentence; Then: gives the last step its own label. The pattern is Pixelmator Pro's Settings, Apple's own Settings panes and our Mac sheet's token tab. Apple's current Human Interface Guidelines no longer spell it out (Layout says only to align components so they are easy to scan); the older Mac guidance called it centre-equalised layout, and Mario Guzmán's Mac layout guidelines keep its rules (labels right-aligned, colons aligned, stacked controls left-aligned). It cost five new strings: miro.appOnce, miro.appEither, miro.appOr, miro.appThen, and miro.stickyShapeLabel (the Mac's Sticky shape:, already translated), replacing the two sentence templates.

Why tabs. The routes are not one form: the board file honours sticky shape and long-quote splitting, but not colour by sentiment, clip links or a board name (the file is always single-colour), while the token route takes all of them. Each tab shows only what applies. A route per app also leaves room for Miro and FigJam to diverge, and for the parked one-click relay to replace the second tab one day without moving anything researchers have learned.

One new element. The two-segment control does not exist in the web report yet (the only tab list is the Inspector panel's); it would be built once as a shared component, with tablist semantics and arrow keys. On the Mac sheet it is the standard segmented control. Everything else is the dialog's existing classes; the rule between the instructions and the settings is the report's own hr (keyline colour), with a smaller margin.

The help button (owner, 9 Nov 2026). On the Mac it is not new: the Miro sheet already has the native one, SwiftUI's HelpLink, bottom-left in both token views (the Pages Export-dialog pattern), opening the token page. The Miro app tab gets the same HelpLink, opening Add quote stickies to a Miro board (bristlenose.app/docs/miro-app.html, written 9 Nov and held on a website branch until this tab ships); the token tab keeps send-to-miro.html. The web dialog has no help button yet, so it is new there, and it is drawn here to look like the native one (a filled grey disc and a dark ?), not as a Bristlenose-styled button. Its label reuses nav.help (Help). The two links go to different places: Add Bristlenose to Miro ↗ is Miro's own install page (pick a team, Add & allow); the ? is our help, the steps with Miro's screenshots.

What is new code. Copy: Bristlenose can be pasted from (the Miro app and the FigJam plugin both read a pasted board, in two flavours) but nothing in Bristlenose puts a board on the clipboard yet. Safari refuses a clipboard write that follows a network fetch outside the click, so the copy is written as a ClipboardItem whose content is the pending fetch (the frontend's known fix).

Not tabbed: the Screens board's Send to Miro. The board file cannot carry screenshots, so that dialog stays token-only.
