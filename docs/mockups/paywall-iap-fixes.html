Paywall fixes before submission

The Mac paywall sheet, before and after four fixes from the 25 Nov App Store review. For approval before any code changes. Rendered by AppKit from the SwiftUI view, not drawn.

Artefact: the sheet as it rendersCommentary: why, and what is new
Appearance:

1 · First Analyse, eligible for the free trial

Commentary
  • The billed amount is now the largest pricing element. Before, "free" was in the title and £9.99 only in footnote grey. Apple's Schedule 2 asks for the billed amount to be the most prominent pricing element; this was the review's most likely rejection.
  • The plan's name is shown ("Bristlenose Monthly"), which 3.1.2 asks for. It is the display name from App Store Connect, read from StoreKit, not typed.
  • "7 days" is read from the store. It is the introductory offer's period, formatted by Foundation in the reader's language. If App Store Connect has no free trial, this state is not shown at all: the lapsed layout below appears instead (the gate changes from "eligible" to "eligible and the product has a free-trial offer").
  • Everything under the price is the shipped sheet, in the shipped order, with the shipped words. Nothing else moves.

2 · Not eligible for the trial (lapsed, or trialled before)

Commentary
  • Same structure as the trial sheet: name, price, then one line, one size down from the title (headline).
  • Your wording, 25 Nov: "Subscribe to do further analysis and studies" (was "Subscribe to keep analysing your studies"), and "Your existing projects are all still here…" (was "Your analysed projects…").
  • One layout for both states means one code path, so the price can't fall back into the footnote in either.

3 · Ask to Buy: the purchase is waiting for a family organiser

Commentary
  • The shipped line promises something the code only sometimes does. Analysis starts on approval only if this sheet is still open when it arrives. After Not Now, a switch to another window, or a quit, nothing starts. Approval usually takes minutes to hours.
  • Proposed: say what actually happens. The other option is to keep the promise in code (remember the study across closing the sheet and relaunching, start it on approval). That is more code and a new behaviour, which your UX gate would need to approve on its own; the honest copy is the minimum change.
