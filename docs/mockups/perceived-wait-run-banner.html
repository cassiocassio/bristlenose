Your question: could the web app ask its platform to send the alert?

Short answer: yes in principle, but it is the wrong place for this one. The thing that knows a run has ended is the Swift side, which already supervises the run; the report page has no run-progress channel at all. Routing it page → bridge → Swift just adds a hop to reach the same notification centre.

  • Inside the Mac app's web view: I could not confirm that the page's own Notification or Push API works there. The commonly described workaround is the one the app already uses for other page-to-app messages: a message to native code, which posts the notification (search-level; Apple's WebKit release notes for the current macOS are the authority).
  • In a plain browser tab (bristlenose serve with no Mac app): the browser's Notification API can raise a banner while the tab is open, after the browser's own permission prompt. That is a fallback for people not using the Mac app, not a route for the phone: Safari's Web Push (macOS 13 and later) needs a service worker, an HTTPS site and Apple's push service, and a page served from the researcher's own Mac cannot be reached from their phone to subscribe (my inference from how Web Push subscribes; not tested).
  • Either way it stays on the Mac. Phone and Watch need route 1 (a service the researcher picks), as in the design note.
