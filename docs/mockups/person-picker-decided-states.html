1 · An unknown speaker

Commentary

1a is the grid as it stands for an unknown moderator under Phase 1: m? and the grey italic role word. 1b is the picker it opens. There is nothing to confirm, so the cursor starts in the new-person row and the researcher just types. The hint is New moderator, the shipped string, here in grey italic. Whether the hint is italic is the open question from the tick page, so 1b and 1c show both. The row shows m3, the next free code after Martin's m1 and Kerri's m2 (§J8.8), not this slot's own.

1d is the guard against duplicates. Typing "Mar" with Martin already known moves the highlight onto Martin, so Return picks the existing person instead of making a second Martin (answer 2: never merge on a name). To make someone new with a matching name, the researcher arrows back to the field. This is the type-ahead the owner anticipated, and it is the one genuinely new interaction on this page.

2 · A known speaker

Commentary

2a: the hover ✕ on the current row only. It means "not this person": the speaker goes back to unknown (1a), and a sticky cleared state keeps the next run from proposing the same name. The ✕ would be the second glyph in Icon.tsx, in the same stroke as the check. Its accessible name is a new string. 2b: clicking the confirmed name turns it into a field. Return renames Martin everywhere he appears (answer 2). A proposed (dotted) row still confirms on the first click.
