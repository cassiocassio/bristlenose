“This recording may have a transcript” — where to say it, and whether it still pays

100days row added 18 Oct 2026 [trust]: when every session to transcribe is a recording whose file name says it came from Teams (or Zoom, or Meet) and none has a transcript beside it, say so before fetching 1.5 GB — the platform may hold a transcript, which the researcher can add and skip the wait. This page checks what is true at HEAD, shows the window in which such a hint can still help, then lays out four places it could appear, with copy, and what each costs and risks.

artefact — what ships (real pixels, shipped strings unless flagged NEW) commentary — why, cost, what it rules out

At HEAD (e5b539b0c, 7 Nov 2026)

  • SHIPPED Pairing by name. _normalise_stem in s01_ingest.py strips the Teams tail (_TEAMS_SUFFIX_RE, two observed specimens), Zoom cloud and web-portal names, Zoom local folders, Meet's dated tail (_GMEET_TAIL_RE) and Bristlenose's own download prefix, so a recording and a hand-fetched transcript become one session, and a session with a transcript never reaches ffmpeg or Whisper (has_existing_transcript). Nothing records which platform matched: the knowledge exists for a moment inside the normaliser and is thrown away.
  • SHIPPED Swift already parses Teams names (TeamsRecordingName.swift, for the import window) and walks a study's folder exactly as run does (ScanSelection, pinned by scan-selection-contract.json). Zoom and Meet have no Swift twins.
  • SHIPPED Teams, Zoom and Meet import windows ship (File ▸ Import; cloud-import-three-platforms.html). But the Teams importer brings no transcript: it is admin-consent only and waits on Phase 3 (TeamsSource.swift: transcript: .needsAdminApproval, "brings no Transcript column"). Zoom import is a Diagnostics-gated beta. So "import from Teams" is not, today, a way to the transcript; downloading it by hand from Teams and dropping it beside the recording is.
  • SHIPPED 22 Oct Apple's model transcribes the first run on macOS 26+ in nine languages while Whisper downloads behind it; on those Macs the run has no download stage at all (_needs_whisper … and not self._apple_speech_run()). The 1.5 GB wait this row targets is now macOS 15, non-Apple languages, Whisper only, or a slow network. See whisper-first-wait-options.html for the lanes.
  • SHIPPED 22 Oct The download starts in the background at the AI disclosure, before any drop (fc2fea73f), so the researcher often does not meet it.
  • DECIDED 23 Oct An analysed session keeps the files it was analysed from (decision #129): a .vtt dropped beside an analysed recording is set aside as added_after_analysis; only Re-analyse reads it (the nuclear option). So the hint has a window, and it closes when transcription starts, not when the report lands.
  • SHIPPED A folder drop auto-runs ("Folder-drop is the explicit signal to analyse"; ContentView.swift). There is no confirm before a first analysis; Re-analyse… has a sheet because it destroys work. The only pre-run resting surfaces are the N files to analyse pane and the +N unanalysed row delta with its popover (for files added later).
  • EXISTS Vocabulary: MessageKind.info (ℹ, info.circle outline, blue) is "a neutral note, no action needed"; the row's glyph rule is "news, not opportunity", and a door only where there is a list with no other home (design-desktop-project-status.md). The shipped Waiting for Whisper row carries its one sentence in the row tooltip (waitingForWhisperHint).
  • OPEN No surface anywhere says "this looks like a platform recording without its transcript" — not the CLI, not the row, not the pane. Cluster 6c of design-platform-transcripts.md ("a doctor check or pipeline warning when a video has no matching transcript") is unticked.

The question, as it stands now

The 18 Oct argument was skip the wait. On macOS 26 there is usually no wait to skip. What survives is the second argument the ingest comments make: a hand-fetched platform transcript gives accurate speaker names from the directory, which no model guesses, and it costs no transcription at all. So: where does a non-blocking hint go, in the short window before transcription starts, that can be wrong without costing the researcher anything, and how is it worded so a false positive is harmless?

Commentary The 18 Oct row assumed the hint sits "before fetching 1.5 GB" and that the fetch is where the researcher is stuck. Two of the four lanes now have no such moment: on macOS 26 the first run transcribes in seconds, and a hint shown then is a hint about a thing already done. The honest window on the common lane is the pre-run surfaces, which exist only when files are added rather than dropped. The drop lane on macOS 15 keeps the original window, three to eleven minutes wide. Any design that only lives in the download stage is therefore a macOS 15 feature.

What the hint would be, in every option

Detection (Python, s01 ingest; single source for CLI and Mac): for each session with media and no transcript file: platform = the rule that changed its stem (teams | zoom | meet), else none hint fires when every such session has a platform, and all are the same platform → reason code platform_transcript_possible, platform, count mixed platforms → fires with platform = "meeting" (owner call: or stay silent) never fires when any session already has a transcript, or when the drop is transcripts only Carried as a reason code and a count on the run (events log / preflight line), never as a sentence and never with a file name: «never an id, filename, speaker label» (events.py). The Mac renders the sentence from the code in its language (rule 1 of desktop/CLAUDE.md: errors carry a case, not a sentence).
Commentary Why Python, not Swift at drop time: Swift knows Teams names only; Zoom and Meet have three regex families each on the Python side, with observed-specimen tests. Porting them is a second copy pinned by a contract (the ScanSelection pattern), affordable but a cost for a hint. Ingest runs within seconds of the drop anyway, and the CLI needs the same detection. False positives: a Teams recording made with transcription off, a recording the researcher is not the organiser of (Teams lets only the organiser download the transcript), a Zoom account with "Create audio transcript" off (the importer already has a sentence for that: cloudImport.zoomTranscriptOff). The copy says may, names no file, and asks for nothing — a wrong hint costs a glance.

Recommendation

C and D together, one sentence, no new control; B held; A not.

  1. Detect once, in Python ingest, and record the platform that matched on the session. Emit it as a reason code with a count on the download-stage progress event, and print the ℹ line in the CLI's preflight block. This is the row as written ("cheap, no engine change") and it is where the file-name knowledge already exists.
  2. C on the Mac: the cover pane's description and the running row's tooltip during the download stage. Nothing blocks, nothing is dismissed; the Stop the researcher may want is the ring they already have. This covers the lane the row was written for (macOS 15, non-Apple languages) for the whole download.
  3. D for the add-files lane, Teams first (Swift already parses it), because on macOS 26 it is the only moment before transcription in which the hint can change anything. Zoom and Meet twins follow with a contract fixture, or wait for C's Python side to be reachable from Swift.
