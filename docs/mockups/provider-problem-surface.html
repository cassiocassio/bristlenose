Commentary · A
  • The trigger decides whether this is useful or a nag. Today the out-of-credit pill lights from a sticky verdict (Settings validation or a failed run) and stays until a top-up and a successful run. For the hand-tagger that is a pill present for months over work that never needed the provider. A′ is the alternative: the pill appears when a call was refused, not when a verdict is merely known.
  • The glyph is the existing MessageKind, not a new one. Rejected key is error (xmark.circle.fill, red; .invalid is red everywhere else); credit and unreachable are warning (exclamationmark.triangle.fill, amber). The words say which. This replaces the amber dot the shipped out-of-credit pill uses, a documented decision to reverse.
  • “Unavailable” has no source of truth. It is a failed observation: the sticky cache the pill reads deliberately doesn’t store it. A pill for it needs new state, and it would sit lit for anyone on a train.
  • Visible on Welcome and in Settings; one fix clears every project at once.

Commentary · B
  • It is the quiet standing marker. Small, secondary, never competing with the work. For a dead key that is allowed to sit for months, that is arguably the right volume.
  • It disappears with the sidebar. Hide the sidebar and the condition is gone; the first frame in the second row. Fine for a quiet marker, poor for something blocking.
  • The footer is a sidebar-width strip. At the 200 pt minimum, version + status + bug leaves about 100 pt, so the status truncates (the first row is already tight).
  • Neighbours. It sits beside Send Feedback and the beta word. The latter is compile-time and goes before the App Store build, which leaves status + bug alone. The code comments also say the plain-text footer was chosen because a capsule read as one of the app’s clickable status pills; a status here has no popover to open, so the fix path is Settings only.

Commentary · C
  • Zero nag, and it matches the hand-tagger. A dead key shows nothing until something actually needs it. No chrome to maintain, no state to clear.
  • Coverage stops at the analyse row. The row exists for runs. A signal-card update or a transcript edit that needs “a few cents” has no row, so a refused call is silent unless it grows its own in-place note (C′). That is a new element on each surface that makes such calls, and I haven’t audited how many there are or which report a refusal over the bridge. The only failure the app currently turns into state is a billing one.
  • One fix, many failures. With N projects a dead key is N “Run failed” rows, each found by trying. The row also says only “Run failed”; the cause is one click away.
  • It finds out late. Someone who drops in eight recordings learns their key is dead when the run starts, not before.

Commentary · what the HIG says (fetched 2 Nov 2026 from Apple’s DocC JSON)
IdeaHIGReads as
Loud once, quiet afterFeedback: match the significance of the information to the way it’s delivered; “display status information in a passive way so that people can view it when they need it”.Supports a passive pill. Prominence belongs to the first occurrence and in place, not to a permanent loud chrome.
Where the first telling goesWriting: show an error “as close to the problem as possible”, avoid blame. Alerts: avoid an alert for information that isn’t actionable; Mail’s answer to an unavailable server is “an indicator that people can choose to learn more”.Stage 1 is the in-place note plus the full-label pill. Not an alert, not a modal. An alert only if a researcher-started action was blocked outright.
Popover as the resolve surfacePopovers: “Avoid using a popover to show a warning. People can miss a popover or accidentally close it.” A Close button only “for confirmation and guidance”.A mismatch with what ships. The out-of-credit popover carries a status and two actions, not a data-loss warning, which is the HIG’s case for an alert. Fine if the first telling is in place (stage 1); not fine if the popover is the only telling.
Expanding a condensed viewPopovers: for “condensed and expanded views of the same information”, animate the change so it doesn’t read as a new popover.Stages 3 → 4 is that case. Animate it, and honour Reduce Motion.
A day, as a timerAccessibility: “Minimize use of time-boxed interface elements… Prefer dismissing views with an explicit action.” Offering help: tips at “once every 24 hours” (a cadence, not a collapse).A live timer changing the toolbar while someone looks at it is the thing to avoid. Evaluate the 24 hours at launch and on window activation, never mid-glance. Nothing is removed by collapsing, so the content stays one click away.
Glyph-onlyButtons: macOS shows a tooltip on hover; tooltips 60–75 characters, “context-sensitive… different text for a control’s different states”.The collapsed pill needs a state-specific tooltip; its accessibility label stays the full text. The glyph is the kind’s own and doesn’t change on collapse, so a collapsed pill is recognisably yesterday’s.
Same colour, different meaningColor: “Avoid using the same color to mean different things.”An amber or red disc in the title bar echoes the minimise and close controls, which is why the lamp works in a Settings list and not here. A triangle isn’t a disc. The red error glyph is a disc, but inside a capsule it isn’t the bare window control; check it at real size.
Don’t look like a countNotifications: “Avoid creating a custom image or component that mimics the appearance or behavior of a badge.”The coloured dot sits on the glyph; no number, ever.
Reachable when hiddenToolbars: “Make every toolbar item available as a command in the menu bar… people can customize or hide” the toolbar. Reduce tinted toolbar controls.Needs a menu twin so the condition can’t be lost to a hidden toolbar or the » overflow. The stage-1 tint is the one place this runs against the grain.
Footer, option BSidebars: “Avoid putting critical information or actions at the bottom of a sidebar. People often relocate a window in a way that hides its bottom edge.”Counts against B directly.
Commentary · how it behaves, and the calls that are yours
  • No ✕ convention for a toolbar pill in the HIG. The closest are system notification banners and tip popovers, which both give people a dismiss and say to “make it easy to dismiss”. A trailing ✕ is a reasonable invention; it is not a precedent.
  • ✕ has to be a separate hit target. StatusPill is one Button that toggles the popover, so a nested ✕ needs its own target beside it. Right-click “Dismiss” isn’t available on a toolbar item (macOS swallows it for Customize Toolbar; already a gotcha in desktop/CLAUDE.md). So the accessible dismiss is the Hide button in the popover (fourth frame), with ✕ as the pointer shortcut. A hover-only ✕ would be unreachable by keyboard and VoiceOver.
  • Dismissed doesn’t mean forgotten. Hide removes the pill; the Settings dot still says “Out of credit”, and the menu twin still opens it.
  • When does it come back loud? The risk in your own rule: a month of transcript edits on empty credit means a month of refused calls, and if each one re-lights the full pill, that is the nag again. Suggested rule: a refusal re-expands the pill only when the condition changed (credit → key rejected) or the call was an explicit AI action such as Analyse or Autocode. An incidental refusal on an already-acknowledged condition gets its in-place note and nothing in the title bar.
  • Clearing. A successful call, a re-validated key, or a top-up removes it at any stage. App-wide state, so hiding it in one window hides it in all.
  • Not checked. The exact SF Symbols (the glyphs here are drawn to suggest them), the ✕’s hit-target size, and how a glyph-only item behaves in macOS 26 toolbar overflow.

Where I land (for you to overrule). They aren’t exclusive. C′ is the primary for the hand-tagger, because that is where the person meets the problem. Add one pill (A′) for the two sticky conditions, key rejected and out of credit, lit by a refused call rather than a stored verdict, so it is the way to fix it and not a months-long reminder. Leave “can’t reach” on C only: it has no source of truth and clears itself. I would not use the footer.

The open call is the persistence rule for the pill that already ships: should out-of-credit also stop showing on a stored verdict alone?
