Can a reload fix it? What reaches this pane

Commentary · research, 24 Oct 2026
CauseReaches the whole-report pane?Does Retry (a reload) fix it?
A throw in a modal’s own body (hooks, values above return)Yes (frontend/CLAUDE.md, R85)Yes: the reload closes the modal. Opening it again crashes again.
A lazy chunk that won’t load: Settings, Miro, FigJam (AppLayout.tsx:997–1010, a Suspense with no boundary)YesYes: index.html is no-cache (app.py:489), so a reload fetches the new hashes. Cases: a CLI upgrade under a running serve, or a blip. On the Mac the bundle can’t change under a running app.
A timing race (async answers arriving in an unexpected order)YesUsually: nothing is persisted.
A throw in AppLayout or unbounded chrome from the study’s dataYesNo: the same data comes back, every reload, until a run or an edit changes it.
A throw from saved per-viewer state: localStorage, report prefs seeded by the shell (R89), sessionStorage (it survives a reload)YesNo: the state is re-read on every reload.
A failed data read (fetch error, 404, 401)No: stores catch it, and lenses render ErrorNotice scope="lens" (R86)n/a
Serve restart or serve downNo: on the Mac a new port changes the URL and the shell reloads the web view itself (WebView.updateNSView), and a dead serve shows the boot pane (N08). In a CLI browser the reload gets the browser’s own error page.n/a
Web content process killed (memory)No: a different WebKit path, not a React thrown/a

Conclusion: Retry has real wins (the first three rows), so it stays on the first crash. A crash that survives one Retry is almost always one of the two “No” rows, and a second Retry would fail the same way. Nothing counts repeats today: the SPA posts each crash, BridgeHandler.reportCrash is one optional that the next crash replaces, and RouteError keeps no state. Retry is window.location.reload(), so the mark has to survive a reload. On the Mac the shell can tell, since “a report-error with no route-change since the last one” is the same as N08’s startedByRetry. A CLI browser has no shell, so it needs a one-key sessionStorage mark set by Retry and cleared on a good mount. That one mark serves both, and the plan picks the mechanism.
