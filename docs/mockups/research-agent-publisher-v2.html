Research agent: the researcher publishing (v2)

Second pass at the publish flow, after a six-reviewer pass on 22 Nov 2026 (code, Mac taste, UX, accessibility, i18n, documentation) and a proportion check. It replaces research-agent-publisher.html, which stays as the record of v1. Still a quick sketch (Tier 1) of a native Mac flow: hand-rolled styles that only suggest AppKit, and every word is proposed copy. Scenario ids match docs/design-research-agent.md §7.1; finding numbers (F1…) refer to the private review log.

What the copy may know. The researcher may be in-house, a consultant, a freelancer or agency staff. Every name in Bristlenose's own copy comes from something a user typed, data Bristlenose holds, or an answer from the system it's talking to.

What changed from v1: a menu command, not a button that lives in one place (F19). "Project" on the Mac (F20). What to make is chosen first (F22). The HTML report left Publish for File ▸ Export Report… (F4). The first request to IT carries no research; you publish once IT has set it up (F1). Every publish, including a republish, goes through the review step (F5). No publish happens while you're away (F6). Files go through a save panel (F24). Person to ask and end date are per project (F12, F13).

The choice comes first (F22), and the fields below are the ones that apply to it. Choosing "An agent pack" dims "Publish to" and "Suggested short name", and the end-date column reads "Files keep working once copied" (F12, F13). The sheet doesn't change size.

Commentary

The biggest change (F1). In v1 Sam emailed IT a container holding 412 participant quotes. That put participant data in an inbox outside "who can ask", beyond any end date, and a container is far over a mail attachment limit. Now the request and setup guide hold no research. IT sets the agent up empty; Sam publishes into it from the Mac. Day 1 and Sam's return five months later become the same publish (frame 7), and the address comes from IT, not from a guess.

Cost: on a freelancer's last day it's a two-step: request in the morning, publish once IT replies. If Sam leaves before IT replies, Priya publishes (if she has the projects) or IT and Sam arrange it.

Share… opens the system share picker, so Outlook, Teams or Slack appear if that's what the researcher uses, instead of assuming Mail (F25). The request is shown in full in a scrolling, selectable view.

The draft holds only what Bristlenose knows: the name, the person to ask. Anything about the researcher's own situation is theirs to add.

Commentary

Sam pastes the address IT sent ("Add a Research Agent by Address…"), signs in with the company sign-in, and from then on it's in this list. Each entry shows its address and who set it up, as the research agent itself reports them, never just a name (F7).

Why: a freelancer with two clients can easily have two research agents both called "What we know about Product X". Picking by name would send one client's participant quotes to the other. Under the hood each needs an id the research agent issues (a build constraint).

This is also how a second researcher, Priya on her own Mac, finds the same agent (P6): the address from IT, then the same list.

No publish waits on IT (F6). v1's "Ask and Publish" published later, possibly days later with nobody at the Mac, from a snapshot that might no longer match what was reviewed (a withdrawal, a new star).
