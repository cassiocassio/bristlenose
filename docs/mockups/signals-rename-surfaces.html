Analysis → Signals: every UX surface

Each artefact below is drawn in the shipped design system and shows the surface as it will read after the change. Highlighter marks the exact new wording. Docs and code identifiers are out of scope here — this sheet is the user-visible set only.

Signals is a feature: the Signals lens, the signal cards it makes, and the signal strength it reports.

Analysis is two things and keeps the word for both — (a) the pipeline running on data, the run the researcher commands, and (b) the human act of interpreting the results of that run.

Test for any string: does it name the signal feature, or does it name a run or an interpretation? Feature → Signals. Run or interpretation → Analysis.

Commentary

Sense (b) is why the rename is worth doing, and the welcome screen already proves it. WelcomeHomeView.swift:131 says "Tagging is analysis — turn quotes into themes." Seven lines later, :138 names a different lens "Analysis". The same file, in the same scroll, asserts that analysis happens in the Quotes lens and then gives the word to a lens that is not it. That is the contradiction in miniature.

analysis.html earns its place by content, not by exemption. The page carries three sibling blocks — Key findings, Section × Sentiment, Theme × Sentiment. Two of the three are heatmaps, so signals.html would name a third of the page. It is also squarely a sense-(b) artefact: the thing you open in order to interpret.

The lens is the opposite case and survives the same objection: its heatmaps are the inspector, reached by drilling into a card and labelled "Heatmap sources". Evidence behind a signal, not a peer section.

Resolved: "Analysis updated" was flagged as worth a second look. It fires from LastRunStore on run completion, so it is sense (a) outright — a run finishing, not a lens being named.
