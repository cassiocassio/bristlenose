Tag hang catalogue

Where a row of tags sits under text in a column, the badge boxes hang left by the badge's own padding, so the words in the tags start on the text's edge. The text aligns; the box hangs. Each surface shows before and after, light and dark. The chrome bar over each frame reports, live, how far each line-starting tag's first letter sits from the first letter of the text above it.

Commentary · the proposal

One variable sets the padding and the outdent, so they can't drift apart. Contexts that use a different padding redefine the variable rather than the rule.

/* Proposed — every rule below is the product CSS, prefixed with .after so it
   applies only to the "after" frames. --bn-badge-pad-x is the one source. */
.after { --bn-badge-pad-x: 0.45rem; }
.after .badge { padding-left: var(--bn-badge-pad-x); padding-right: var(--bn-badge-pad-x); }

/* 1. Quote cards — Quotes, Screens, Discussion, the uncategorised floor */
.after .quote-card .badges { margin-left: calc(-1 * var(--bn-badge-pad-x)); }

/* 2. Transcript margin — its own tighter pad, same rule */
.after .margin-tags { --bn-badge-pad-x: 4px; margin-left: calc(-1 * var(--bn-badge-pad-x)); }
.after .margin-tags .badge { padding: 1px var(--bn-badge-pad-x); }

/* 3. Dashboard featured quote — the badge alone, since it shares a wrapping row */
.after .bn-featured-footer > .badge { margin-left: calc(-1 * var(--bn-badge-pad-x)); }

/* 4. Codebook groups — the row's own 4px inset has to go too */
.after .codebook-group { --bn-badge-pad-x: 0.5rem; }
.after .codebook-group .badge { padding: 0.2rem var(--bn-badge-pad-x); }
.after .codebook-group .tag-name-area { margin-left: calc(-4px - var(--bn-badge-pad-x)); }
.after .codebook-group .group-total-row { padding-left: 0; }

/* Experiment for 1, not proposed: hang the speaker badge too (pad + 1px border) */
.after.with-speaker .quote-card .speaker .bn-speaker-badge--split { margin-left: calc(-1 * (0.4rem + 1px)); }

1 · Quote card — the tag row under the quote

.quote-card .badges · molecules/badge-row.css · rendered by QuoteCard.tsx on Quotes, Screens (ScreensLens.tsx), Discussion (DiscussionLens.tsx, its own markup with the same classes) and the uncategorised floor

Hover: the × circles and the proposed badge's action pill

A quote with no tags yet: the add button starts the row

Should the speaker badge hang too? Only if it starts a line, and it doesn't always

Screens lens — the same card, compact (screens.css rules inlined)

Commentary

Every wrapped line's first tag hangs, because the outdent is on the flex-wrap container, not on a badge. The words of Confusion and workaround start on the quote's own left edge, under the opening quotation mark.

The row gets 7.2px wider, because a negative margin on a block widens it. So a row can wrap differently after: here expectation mismatch moves up beside Confusion in the 387px card.

Proposed and add badges land 1px off (the +1.0 readings). Both draw a 1px dashed border that a solid tag doesn't, so their words sit 1px further in. To fix it, take 1px off their side padding: .badge-proposed, .badge-add { padding-inline: calc(var(--bn-badge-pad-x) - 1px) }. Their boxes then also match a solid tag's width, so accepting a proposal no longer shifts the row by 2px. That fix isn't in the after frames, so you can see the 1px it addresses.

The × circles and the action pill sit on the badge's right, so hanging left doesn't move them. Nothing to the left clips: the card edge is 72px from the hung box, and no ancestor between them sets overflow.

The speaker badge shouldn't hang. It follows the quote on the same line whenever it fits, and only drops to its own line when it doesn't. Hung, the wrapped case lines up, but the inline case runs over the closing quotation mark. CSS can't tell the two apart. Hanging only the tags leaves the speaker box 7.2px right of the tag boxes in the wrapped case. That's the one visible cost.

Screens renders QuoteCard, and Discussion renders its own blockquote.quote-card with the same .badges row, so one rule covers both. No trial project has Screens or Discussion data, so neither was measured live; the compact frame measures the rule against the Screens card's own CSS.

2 · Transcript margin — tags under the section label

.margin-tags · molecules/transcript-annotations.css · components/Annotation.tsx

Commentary

Tighter padding here (4px, not 0.45rem), so the variable is redefined on .margin-tags and the same calc() follows it. The label and the tag words then share one edge.

The × circles stay clear, because .margin-tags keeps its 2px top and right padding for them, and the outdent is on the left. Below 800px the margin drops under the segment text, aligned with the body column, and the hang then lines the tag words up with the transcript's words instead.

The +1.0 on the last tag is the proposed badge's dashed border, as in §1.

3 · Dashboard featured quote — conditional

.bn-featured-footer · organisms/global-nav.css · Dashboard.tsx

At the width it ships (3 cards at 1440px): the badge wraps to its own line

Wider card: the badge stays on the timecode's line

Commentary

The badge shares a flex-wrap row with the timecode and the speaker. It starts a line only when the card is too narrow to hold all three, and CSS can't tell which case it is in.

Narrow, the hang works: the badge's words line up with the quote and the timecode's bracket. Wide, the same rule eats into the 16px gap after the speaker badge, leaving about 8.8px. Two ways out: give the sentiment its own line always (a markup change in Dashboard.tsx), or leave this surface alone. The card clips (overflow: hidden) and the hung box stays 16.8px inside it.

4 · Codebook groups — tags under the group title

.codebook-group .tag-row · organisms/codebook-panel.css · CodebookAuthoring.tsx (both read-only framework groups and your own codebook's rows)

A framework group with a subtitle (Bristlenose UXR Codebook ▸ Behaviour)

Commentary

The pure hang doesn't reach here. The row already insets its badge 4px (the row's own padding, which draws the drag and merge-target box), so the words sit 12px right of the group title, not 8px. The after frame takes out both: margin-left: calc(-4px - pad) on .tag-name-area, and the TOTAL row's 4px too, so title, tag words and TOTAL share one edge.

The cost: the badge box now pokes 8px out of the row's box, which is what lights up as a merge target (.tag-row.merge-target box-shadow) and when you drag. The selected badge's outline moves with the badge. Hung box to card edge: 5px.

Your own codebook's rows (TagRow in CodebookAuthoring.tsx) have the same .tag-row > .tag-name-area > .badge shape, and the inline rename field is a .badge too, so it hangs with the tag it replaces. Measured here on framework groups, which this trial project has; its own codebook is empty.
