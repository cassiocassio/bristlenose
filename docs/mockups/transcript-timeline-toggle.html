Transcript: the journey chain or the timeline, in one sticky slot

The transcript's sticky header keeps today's skinny journey chain by default. One button at the end of the row swaps it for the session timeline from the Sessions grid, in the same sticky slot, scaled to this one session. While you read, a window on the timeline covers the paragraphs on screen.

The slot

One sticky header, as today. Skinny: the chain, unchanged. Fat: the timeline takes the chain's place on a second line; the session label and the participant's name stay on the first. Section flags are the chain's own waypoints (first quote of each run, revisits included), so nothing is lost by hiding the chain.

Does a marker track scroll? A range does, a playhead doesn't

Reading is a range, not a moment, so scroll moves a reading window: the time from the paragraph under the header to the last one on screen, interpolated within each, recomputed once per frame. It uses the minimap's viewport tokens, the house mark for "what you are looking at", and dragging it scrolls the page as the minimap's does.

The current section's flag stays raised, the fat equivalent of the chain's active pill, by the chain's rule: the last waypoint above the header's bottom + 8 px.

The playhead stays a player thing. The thin hover cursor is the shipped one (where a click lands). A heavier accent mark with a head shows the player's time, only while media plays. Press Play above: PlayerContext already centres the playing paragraph, so the window follows the player without any new code.

A click scrolls, never navigates

  • Flag: the chain's own handleIndexClick (smooth scroll to the waypoint, 600 ms observer lock).
  • Speaker lane: the paragraph holding that moment, by resolveSegmentForSeconds, the resolver #t- deep links already use, with the anchor flash.
  • Sentiment bar: straight to its quote. No popover: on this page the quote is the text itself.
  • The URL takes #t-<s> by replaceState: shareable, and Back still leaves the page. The readout under the frame shows what would be written.

So onJump is the one seam: the Sessions grid passes "navigate to /report/sessions/s3#t-589"; the transcript passes "scroll here".

Opening it keeps your place

The header grows by the timeline's height, so the page compensates scrollTop: the paragraph under the header is still under it. --bn-journey-header-height (the anchors' scroll-margin-top) is measured today on labels and speakers only; the mode joins those deps.

Scale

One session, so it fits its own duration to the width (no shared project scale). Clips or slivers by the shipped 2.5 s/px threshold: a 34-minute session at this width draws clips; a 60-minute one at a narrow window falls to slivers. No zoom slider in the slot for v1, so there's never a sideways scrollbar.

2 · How tall it can get: a third of the window, sentiment goes first

Each frame is the sticky slot alone at the live frame's width, same reading window, same current section. The bars measure each slot against the window height chosen above; the tick is one third.

The budget

The sticky slot may take at most a third of the window. The rest is the reading area, and the transcript is what the page is for.

The ladder: shed detail before structure

  • 3 lanes by default: sections, speakers, sentiment. They answer "where am I, who's talking, how did it go".
  • Themes never ride in the sticky slot. The margin already names them beside the text, and their three packed rows cost more than any other lane.
  • When 3 lanes would pass a third, sentiment goes, leaving flags and speakers. Try 560 px in the live frame.
  • It never falls back to the chain by itself, because a pressed button that shows the chain would be lying. Below about 410 px even 2 lanes pass a third. I suggest we accept that: the researcher can turn it off. Try 400 px.

The tapestry's 14 px under the timecodes is room for macOS's overlay scrollbar. With no zoom in the slot there's no scrollbar, so that space could go: a cheap saving if the owner wants it, not taken here.

3 · The toggle

The right end of the sticky row, in each state, light then dark.

One button, not a segmented pair

The chain is the resting state and needs no glyph of its own; the button names what it adds, like the Mac's show/hide toolbar toggles (the sidebar, Xcode's inspectors). aria-pressed, with the shipped string sessions.tapestry.label ("Session timeline") as its name and tooltip, so the web needs no new copy.

Pressed takes no further hover change, as a selected .dimension-btn takes none; the pointer and the tooltip carry it.

Glyph: Lucide chart-gantt on the web (a new timeline concept in Icon.tsx); calendar.day.timeline.left on the Mac. SF Symbols can't be drawn in a browser engine (house rule), so the Mac half is named, not shown.

The alternative, last row (flagged): .dimension-toggle with Lucide route ↔ chart-gantt (SF point.topleft.down.to.point.bottomright.curvepath ↔ calendar.day.timeline.left). Rejected: two glyphs to learn for one decision, and this house's segmented controls carry words, not icons.

On the Mac

The View menu gets Show Session Timeline / Hide Session Timeline, with the SF Symbol, enabled on a transcript and greyed elsewhere, mirroring the button's state. No keyboard shortcut is proposed (shortcuts are earned). These are the only new strings, and they're for the owner to write.

For the owner to decide

  • Remembered how? Per viewer it's a convenience, but localStorage does not survive quitting the Mac app. Forget on quit, or a native mirror like the subtitle prefs?
  • A session with no sections has no chain, but it still has a timeline (clips and sentiment), so the button stays.
  • Export: /tapestry is already embedded, so the timeline works offline. The hover thumbnail stays serve-only, as it is in the grid.
