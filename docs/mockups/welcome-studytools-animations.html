⌗ · Full-bleed slot — flush left, equal right, and “as deep as makes”

The cell is a SQUARE that scales with the viewport — that's the constraint everything here has to survive, so resize the window and watch these two panels. Arithmetic from WelcomeHomeView.swift: the spiral is framed width: w, height: w / 1.618, and GoldenSplit(.horizontal) hands the major cell width: (w − 8) × 0.618; its height is the spiral's full height, 0.618w. Both ≈ 0.618w → square, growing linearly with width. (These side-by-side panels are each ~half the page, so slightly smaller than the real cell, which is ~62% of the whole content width — the proportions are faithful, the absolute size is conservative.)

The proposed rule. The illustration shares the cell's content edge — 16pt left, 16pt right (the real welcomeCell(large:) padding, the edge STUDY TOOLS already sits on) — runs the full width, stays leading so that when it hits a max width the slack opens on the right, and grows downwards to fill the depth it's given. The CTA then lands on the bottom instead of floating mid-cell. The φ-geometry does not move — the cell is the same fixed square either way; only the content inside it bends, which is the Parthenon rule working rather than being broken. The fake tool below (Trace a theme) is a fixture, not a roadmap item — it exists to prove the mechanism, and it fills its box by measuring it.

proposed — full width, as deep as makes, CTA on the bottom · red = the collision zone
  • “As deep as makes” is a measuring job, not a bigger number. The fixture renders quote cards one at a time and stops when the next one would overflow (scrollHeight > clientHeight), re-running on resize — so the same illustration shows 2 cards in a short cell and 4 in a tall one. Contrast today's illustrations, which are fit-and-centre: the four flow webviews are body{display:flex; align-items:center} and the one still-scaled one (Signals) clamps at Math.min(0.9, …), so handing either a taller box just adds air, never content. Relaxing the frame alone changes nothing on screen — each illustration has to be rebuilt to stretch. That's the content-design half.
  • The CTA bottoms out ABOVE the 26pt nav row — settled, and it's what dodges the red zone. A CTA pinned to the cell's true bottom edge would land in the leading chevron disk's hit band (red). That bug has already been fixed once: 25 Jul 2026 the full-height chevron strip was stealing clicks from the leading Learn → link, and the fix scoped the tap to the disk band alone, bottom-aligned, commented “hit area = disk band only (dots row level, clear of the link above)”. Stopping the CTA above the nav row keeps exactly that clearance, still reads as “on the bottom”, and needs no change to the chevrons. The red marker stays in this fixture as the reason the CTA stops where it does.
  • The bottom of the cell belongs to the Drop-a-folder card — it's a fixture, not a tenant to evict. It rules off the square and is the final implicit CTA. So the target for the illustration + CTA is the bottom of the slot's content area, above the 26pt nav row and above the drop card — which is what both panels show. Not an open question.
  • Because the cell is square, the illustration's box SWINGS in aspect ratio. Everything else in the cell is fixed semantic type plus two fixed rows (nav 26 + drop card), so the furniture is a near-constant ~210–230pt of depth no matter how big the square gets. The illustration takes the remainder — so at a ~400pt cell it's roughly 400×170, a 2.4:1 letterbox, and at an ~850pt cell it's roughly 850×620, near 1.4:1. That swing is the actual design brief. It's also why “grow by quantity” beats “scale one composition”: a stack of cards reads correctly as a wide strip and as a deep column, whereas a single fixed composition can only be right at one aspect. Drag the window across the range and watch the card count change.
  • Max width, expressed how? “Slack opens on the right” needs a max — but an absolute pt value will read differently at each window size, since the cell width comes from the golden split. Cheapest honest rule: let the illustration declare a max in ems of its own type (a measure, like body copy) so it stops widening when the line gets uncomfortable, not at an arbitrary pixel.
  • One illustration doesn't fit this model. Signals is absolutely-positioned and centre-scaled — it'd have to become a normal-flow, left-origin layout first. (Connect an AI agent was, 14 Aug 2026: full-width normal flow, type up a notch.) The book shelf is the other exception: it renders its own caption and link, so it owns its bottom edge and shouldn't be stretched.
