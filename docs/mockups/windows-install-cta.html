Windows on the homepage: two ways to drop irm | iex

Mockup for approval, 19 Nov 2026. The panels are drawn at the real hero-panel size and tokens. The flow under each shows what a researcher sees next, with the friction marked in orange. Facts about the installer are read from packaging/windows/bristlenose.iss: per-user, no admin, x64 (Arm runs it under emulation), adds itself to the user PATH, no Start menu entry and no launch at the end.

Option A

The winget line

Windows

>winget install --id Bristlenose.Bristlenose -e --source winget Copy Setup guide

Free and open source, in beta · Windows 10 or 11 · Paste it into Terminal. No admin rights needed

What happens next

1 · Open a terminal
Start ▸ type "terminal"
Windows Terminal or PowerShell.
The researcher has to know how to open one.
2 · Paste, Enter
> winget install --id Bristlenose.Bristlenose -e --source winget Found Bristlenose [Bristlenose.Bristlenose] This application is licensed to you by its owner. Downloading ... Successfully installed
No SmartScreen dialog expected: winget installs from Microsoft's catalogue (not yet seen on a client edition).
3 · Open a NEW terminal
Path environment variable modified; restart your shell to use the new value.
The window they just used does not know bristlenose yet (measured on 19 Nov). Our page must say it.
4 · Run it
> bristlenose configure claude > bristlenose C:\interviews
Same commands as the guide.
Commentary.
  • Trust: the strongest of the three. Microsoft's catalogue scans the installer before it lists it, so an unsigned-publisher warning is not expected there (untested on a client edition), and there is no "run a script from a website" step. That is exactly what irm | iex lacks.
  • Staleness: winget serves 0.36.0 today, ten versions behind. Moderation took about 33 days for the first package. The page must not go live with this until the new version has merged, or Windows users get a much older build than the Mac gets.
  • Audience fit: it is still a pasted command in a terminal, so it removes the script risk, not the terminal. A researcher who has never opened PowerShell stumbles at step 1.
  • winget may be missing on older Windows 10 (App Installer) and on Windows Server before a desktop logon. A fallback link to the setup guide covers it.
Option B

The download button

What happens next

1 · Click
Edge · Downloads
bristlenose-…-setup-x64.exe
"isn't commonly downloaded. Make sure you trust it" ⋯ Keep
Edge or Chrome may hold it back first and ask them to press Keep.
2 · SmartScreen
Windows protected your PC
Microsoft Defender SmartScreen prevented an unrecognised app from starting.
More info
Don't run
The installer is unsigned. "Run anyway" only appears after "More info". Our note under the button prepares them, but this is the worst moment on either path.
3 · The installer
Setup — Bristlenose
Install ▸ Next ▸ Finish
no admin prompt, no options
Familiar. Per-user, no UAC.
4 · Then… nothing
Start menu
No Bristlenose entry. Finish closes the wizard.
They must still open a terminal and type bristlenose. The button saved the install step, not the terminal.
Commentary.
  • Approachability: best first impression for someone who has never used a terminal: it looks like every other Windows app.
  • The SmartScreen wall: unsigned means "Windows protected your PC" with the safe-looking button on top. A nervous researcher on a client laptop may well stop there. Signing would fix it, but certificates cost money and an unknown publisher still scores low for weeks.
  • The promise is only half kept: Bristlenose is a command-line tool on Windows. After Finish the researcher still has no icon and no window. Without a Start menu shortcut or a "Open a terminal here" finish step, this button feels broken. That is a product gap, not a page-copy gap.
  • Hosting: the file would link to the GitHub Release asset, so the filename carries the version and the button's link must be bumped each release (or point at a stable /download/windows redirect on our site).
  • Corporate machines: unsigned downloads are often blocked outright by IT policy, where winget (policy-allowed source) sometimes is not. Neither is guaranteed.

Recommendation. Ship A first as the primary on the Windows panel the day the bumped version merges, with the setup guide as the fallback link. Hold B until the installer gets a Start menu entry that opens a terminal (or the app ships a window), because the button promises an app and the installer delivers a command. If you want B sooner, lead with the download button but keep the winget line next to it, as drawn, so there is a path with no warning. The interim (before the bump merges) is the awkward bit: the install page keeps irm | iex in the guide, but the homepage can show the download button alone, since the Release asset can be current while winget is not.
