## Tooling & dependency gotchas

Long entries from this section are indexed under **Gotchas** below (theme: Build, bundle size and tooling).

- **Vite 8 uses Rolldown** (Rust bundler) instead of esbuild+Rollup. Build is ~3x faster. `rollupOptions` in `vite.config.ts` is auto-converted by the compat layer. A clean build emits **no** `INEFFECTIVE_DYNAMIC_IMPORT` warnings — if one appears, a page wrapper has re-introduced a static island import that defeats code-splitting (see the island code-splitting bullet under Build & type-checking)
- **TypeScript 6 is stricter about mock types** — `ReturnType<typeof vi.fn>` no longer assignable to concrete function signatures. Use specific function types or `any` for test mocks
- **`react-hooks/purity` flags `Date.now()` in an event handler declared in the component body** — the rule cannot tell a handler from render code, so `const onKey = (e) => { const now = Date.now(); … }` fails lint as "impure function during render". Use the event's own `e.timeStamp` (the time the event happened, which is what a type-to-jump buffer wants anyway) rather than disabling the rule; `PickerSpecimen.tsx` is the worked case
- **Vitest 4 `clearAllMocks` vs `restoreAllMocks`** — `restoreAllMocks` no longer reliably clears mock call counts in some scenarios. Use `clearAllMocks` in `beforeEach` when asserting call counts

## Architecture

Long entries from this section are indexed under **Gotchas** below (theme: Architecture).

- **`main.tsx` dual mode** — SPA mode (`#bn-app-root` exists → `RouterProvider`) vs legacy island mode (dynamic `import()` → individual `createRoot()` calls). The legacy path uses `Promise.all` for code splitting — islands load async, not synchronously like the old static imports. SPA mode is active in serve mode; legacy mode covers the static render path and transcript HTML files during transition

- **Module-level stores (not React Context)** — `QuotesContext.tsx`, `SidebarStore.ts`, and `ActivityStore.ts` use plain module-level state + `useSyncExternalStore` (React 18). Proven pattern, simpler than Context, doesn't depend on tree structure. `QuotesContext` owns quote mutations and toolbar filter state. `ActivityStore` owns background job tracking (e.g. AutoCode) — rendered from `AppLayout` so activity chips persist across tab navigation
- **Backward-compat shims** — `src/shims/navigation.ts` installs `window.switchToTab`, `window.scrollToAnchor`, `window.navigateToSession` as functions that delegate to React Router `navigate()`
