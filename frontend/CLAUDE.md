# Frontend (React / TypeScript / Vite) Context

## What this is

Vite 8 (Rolldown) + React + TypeScript 6 + React Router SPA. As of 30 Aug 2026: 62 components in `src/components/`, 20 islands in `src/islands/`, 10 page wrappers in `src/pages/`, 1 layout in `src/layouts/`, 17 hooks in `src/hooks/`, 2 shims in `src/shims/`, 10 stores in `src/contexts/`, and 1694 Vitest 4 tests across 113 test files. **Measure, don't quote** — every count above was stale by 30–100% before this line was trued, because prose counts rot silently and nothing fails when they do:

```bash
cd frontend/src && for d in components islands pages layouts hooks shims contexts; do echo "$d: $(find $d -maxdepth 1 -type f \( -name '*.ts' -o -name '*.tsx' \) ! -name '*.test.*' ! -name 'index.ts' | wc -l)"; done
```

`npm run dev` proxies to FastAPI. **`npm run build` writes to `../bristlenose/server/static/`, not `frontend/dist/`** — `outDir` in `vite.config.ts`, and the reason serve mode picks a build up without a copy step. See `docs/design-react-component-library.md` for build sequence.

## Build & type-checking

- **Bundle size gate** — `npm run size` (after `npm run build`) measures gzip size of the **live SPA in English** and checks it stays under 220 kB. Current ~196 kB (Node 24 gzip output; ratcheted **down** from 230 kB on 1 Jul 2026 after fixing the dual-import that defeated island code-splitting, then a further drop on 3 Jul 2026 when the `preflight-*` locale chunk was finally added to the exclude glob — see below). CI enforces this. The glob explicitly excludes lazy locale chunks — it must name **all 9 namespaces** (`common/settings/desktop/enums/cli/doctor/pipeline/preflight/server`); `preflight-*` was missing until 3 Jul 2026, so every locale's preflight chunk (14 of them) was wrongly counted, inflating the measured size ~24 kB toward the ceiling. **When you add a namespace, add its `!…/assets/<ns>-*.js` exclude.** The glob also excludes the dev-only `visual-diff` entry, `ResponsivePlayground` + `Playground*` dev chunks, and the six non-landing tab islands (`TranscriptPage`, `Toolbar`, `QuoteSections`, `QuoteThemes`, `CodebookPanel`, `AnalysisPage`) which now code-split into per-tab lazy chunks (only `Dashboard`, the landing route at `/report/`, loads on first paint and stays counted). Add new exclusions when introducing new dev-only or lazy-loaded chunks; if in doubt, leave it in the budget. Ratchet the limit down as optimisations land. The earlier 320 kB sum-of-everything metric overcounted by ~110 kB by including chunks that never load — see [docs/private/bundle-size-analysis-2026-05-02.md](../docs/private/bundle-size-analysis-2026-05-02.md) for the full breakdown
- **Island code-splitting — one dynamic owner per island.** The 6 tab islands (+ `Dashboard`) are `React.lazy`-loaded by their page wrappers (`src/pages/*Tab.tsx`); the `<Outlet/>` in `AppLayout` provides the shared `<Suspense fallback={null}>` boundary. **Do not also statically import an island from its page** — the legacy island mode in `main.tsx` already dynamically imports all of them, so a static import anywhere makes Vite/Rolldown emit `[INEFFECTIVE_DYNAMIC_IMPORT]` and silently fold the island back into the main/`components` chunk (it never code-splits, and the size gate creeps up). Each island needs exactly one owner that imports it dynamically. This was the root cause of the 215→220→230 kB ceiling creep fixed on 1 Jul 2026. A clean `npm run build` emits **zero** `INEFFECTIVE_DYNAMIC_IMPORT` warnings; if one reappears, a page has re-introduced a static island import
- **The `components/index.ts` barrel is in the always-loaded chunk — a component only lazy islands reach must be imported by path, not through it.** `main-*.js` statically imports `components-*.js` and `index.html` modulepreloads it, so *anything the barrel re-exports is first-paint weight*, however lazily its consumer loads. Moving shared code **out** of an island and into `src/components/` therefore has a cost the island never had: the codebook authoring apparatus (`CodebookAuthoring.tsx`, ~9.7 kB raw) went from the excluded `CodebookPanel-*.js` chunk straight into `components-*.js` on 30 Aug 2026 purely by being added to the barrel, charging the landing route for markup no first paint renders. Importing it as `from "../components/CodebookAuthoring"` at both call sites moved it back into its own lazy chunk that the two codebook islands share. **The size gate does not catch this** — it counts `assets/*.js` and subtracts a hand-maintained list of *filenames*, so a shared chunk moving between counted files is roughly size-neutral in the number while being very much not neutral on the wire. **Verify the real thing instead:** `grep -o 'assets/[A-Za-z0-9_-]*\.js' ../bristlenose/server/static/index.html | sort -u` is the actual first-paint set; if your new module's chunk is in it and it belongs to a lazy route, use a path import. Rule of thumb: the barrel is for primitives every lens uses (`Badge`, `MicroBar`, `ConfirmDialog`); it is not for a feature two routes happen to share
- **`npm run build` runs `tsc -b` which type-checks test files** — `tsconfig.json` includes `src/` which contains `*.test.tsx` files alongside source. Vitest has its own type context (looser), so tests may pass while `tsc -b` reports errors. Always run `npm run build` before committing frontend changes, not just `npm test`. Common culprits: `globalThis.fetch` (not `global.fetch`), window casts need `(window as unknown as Record<string, unknown>)` (double cast via `unknown`), and mock data must include all required type properties. **Two more, both from 22 Aug 2026 and both in the same test file within one hour:** (1) **Node builtins have no types here** — `@types/node` is not installed and `tsconfig.json`'s `types` array lists only `vitest/globals` + `jest-dom`, so `import { readFileSync } from "node:fs"` runs fine under Vitest and fails the build with TS2591. To read a repo file from a test, import it (`resolveJsonModule` is on) rather than adding a dependency — reaching outside `frontend/` is already house practice via the `@locales/*` alias and `include`. (2) **A widened union flowing into a narrow call** — a fixture typed `[number | string, string][]` passed straight to a `(n: number) => string` type-checks nowhere but looks fine in the test run. Narrow once at the boundary. The pattern to take from both: `npm run build` is not a formality after a green `npm test`, it is a *different* checker, and test files are exactly where the two disagree

## Tooling & dependency gotchas

- **Primary Node version is pinned in `.tool-versions` at the repo root** (currently `node 24` LTS — bump in one place, CI reads it via `setup-node`'s `node-version-file:`). ESLint 10 dropped Node 23; **Node ≥ 25 breaks jsdom's localStorage** (native Web Storage API conflict — confirmed on 25 and 26: Node's native `localStorage` global is a `--localstorage-file`-gated getter that resolves to `undefined` and shadows the Storage jsdom installs, so any test touching `localStorage` throws `Cannot read properties of undefined`). **If Vitest produces a large number of `localStorage` failures, the first thing to check is `node --version`** — not jsdom, not the test-setup (do NOT add a test-setup polyfill — the fix is the version pin). Run tests with `PATH="/opt/homebrew/opt/node@24/bin:$PATH"` if you default to a newer Node (mise/asdf aren't installed locally, so `.tool-versions` does not auto-apply to your shell). This cost a full hour of mis-diagnosis in Apr 2026 (140+ tests apparently failing on main; actually all passed once we switched to Node 24)
- **ESLint is held at 9 — do NOT re-bump to 10.** `eslint-plugin-jsx-a11y` (latest 6.10.2) peer-caps at `eslint@^9` and has no eslint-10 release. So `eslint` + `@eslint/js` are pinned to `^9.39.4`. If you bump them to 10, a clean `npm ci` fails ERESOLVE and the **blocking** `frontend-lint-type-test` CI job goes red (this exact regression landed 2 Jul 2026 via `7cc28c44`, fixed 3 Jul via `e449aad3`). Re-bump only once jsx-a11y ships eslint-10 support (bump the plugin in the same commit). With eslint 9, `npm ci` / `npm install` resolve cleanly — **no `--legacy-peer-deps` needed** (the old flag requirement, from `typescript-eslint@8.57.x`'s `typescript<6` peer, is gone as of 8.59.1)
- **Reconcile the lockfile with plain `npm install`, never `rm package-lock.json && npm install`.** A full re-resolve silently drifts unpinned transitives to latest-matching (seen 3 Jul: vite 8.0.10→8.1.3, which re-folded the en-locale chunks and blew the size gate 213→233 kB). Plain `npm install` against the existing lockfile changes only what the `package.json` edit requires and leaves everything else pinned. Verify a dep change with `git diff --stat frontend/package-lock.json` and confirm bundle deps (vite/i18next/@vitejs) are untouched
- **Vite 8 uses Rolldown** (Rust bundler) instead of esbuild+Rollup. Build is ~3x faster. `rollupOptions` in `vite.config.ts` is auto-converted by the compat layer. A clean build emits **no** `INEFFECTIVE_DYNAMIC_IMPORT` warnings — if one appears, a page wrapper has re-introduced a static island import that defeats code-splitting (see the island code-splitting bullet under Build & type-checking)
- **TypeScript 6 is stricter about mock types** — `ReturnType<typeof vi.fn>` no longer assignable to concrete function signatures. Use specific function types or `any` for test mocks
- **Vitest 4 `clearAllMocks` vs `restoreAllMocks`** — `restoreAllMocks` no longer reliably clears mock call counts in some scenarios. Use `clearAllMocks` in `beforeEach` when asserting call counts

## Architecture

- **`main.tsx` dual mode** — SPA mode (`#bn-app-root` exists → `RouterProvider`) vs legacy island mode (dynamic `import()` → individual `createRoot()` calls). The legacy path uses `Promise.all` for code splitting — islands load async, not synchronously like the old static imports. SPA mode is active in serve mode; legacy mode covers the static render path and transcript HTML files during transition
- **Module-level stores (not React Context)** — `QuotesContext.tsx`, `SidebarStore.ts`, and `ActivityStore.ts` use plain module-level state + `useSyncExternalStore` (React 18). Proven pattern, simpler than Context, doesn't depend on tree structure. `QuotesContext` owns quote mutations and toolbar filter state. `ActivityStore` owns background job tracking (e.g. AutoCode) — rendered from `AppLayout` so activity chips persist across tab navigation
- **Backward-compat shims** — `src/shims/navigation.ts` installs `window.switchToTab`, `window.scrollToAnchor`, `window.navigateToSession` as functions that delegate to React Router `navigate()`

## Gotchas

### React patterns

- **Two quote-card features are parked behind flags — the code is live-looking but unreachable, and that's deliberate.** `src/utils/featureFlags.ts` gates the **moderator-question pill** (`quotes.showModeratorQuestion`, `.moderator-pill`, `.quote-hover-zone`, the `moderator-question` endpoint) and **quote context expansion** (`ExpandableTimecode`, `ContextSegment`, `useTranscriptCache`, the `expansionReducer` in `QuoteGroup.tsx`). Both were built, tested and shipped, then withheld on 5 Aug 2026 as not-intuitive-enough; the rationale and the revisit checklist live in `docs/design-moderator-question-pill.md` and `docs/design-quote-context-expansion.md`. **Consequences to know before you touch any of it:** (1) the code is not dead — don't tree-shake it, don't delete the "unused" hook, don't strip the CSS atoms; (2) `QuoteCard.test.tsx` runs with **both flags forced on** so the parked behaviour stays specified, plus a "parked features" describe that resets them and asserts what actually ships — a flag flip fails those tests immediately, which is the point; (3) the server endpoint, API helper, export embed key and all 20 locale strings stay live and tested, so only the client affordance is withheld. Flipping a flag on is a design decision; if a revisit concludes the feature isn't worth finishing, delete feature and flag together
- **Clipboard copy after async fetch (Safari)** — `navigator.clipboard.writeText()` fails in Safari if called after an `await fetch()` because the user gesture context expires during the async gap. The fix: use `ClipboardItem` with a `Promise<Blob>` value and call `clipboard.write()` **synchronously** in the gesture handler. The browser resolves the promise internally while keeping the gesture alive. **Critical:** `clipboard.write()` must NOT be inside `.then()` — that makes it async and breaks Safari. Fallback for jsdom (no `ClipboardItem`): `writeText()` after fetch (acceptable in tests). See `ExportDropdown.tsx` `handleCopyQuotes`
- **Bulk actions on multi-selection** — `QuoteGroup.tsx` handlers (`handleToggleStar`, `handleToggleHide`, `handleTagAdd`) check `selectedIds` from FocusContext. If the clicked quote is in the selection, the action applies to all selected quotes. **Star direction**: click-based bulk uses the clicked quote's toggle intent (`newState`) as direction — click an unstarred star → star all, click a starred star → unstar all. This differs from the keyboard `s` shortcut in `useKeyboardShortcuts.ts`, which uses focused-quote heuristic (appropriate when there's no specific click target). **Hide**: bulk hides all selected with CSS collapse (no ghost animation), then clears selection. **Tag**: tag commit applies to all selected quotes with flash animation on each
- **Quote edit keydown handlers must `stopPropagation()`** — `handleCardKeyDown` (crop mode) and `handleEditKeyDown` (hybrid mode) in `QuoteCard.tsx` handle Enter/Escape. Without `stopPropagation()`, the keydown bubbles to the TimecodeLink `<a>`, the browser synthesizes a click, and `player.js`'s document-level click listener opens the video player. Both handlers need `preventDefault()` + `stopPropagation()`. See bug #9 in `docs/design-quote-editing.md`
- **`addTag()` dedup guard** — `QuotesContext.tsx` `addTag()` rejects case-insensitive duplicate tags (returns `prev` state unchanged). This is the single source of truth for all tag additions — fixes apply to manual adds, proposal accepts, etc.
- **A `getCodebook()` result is a mount-time snapshot — QuotesStore is the fresher source of "which tags exist".** `putTags` is fire-and-forget (`firePut` returns `void`), so a tag the researcher just typed exists in `QuotesStore` well before any refetch could see its new `TagDefinition`. Only `CodebookPanel` and `AppLayout` (AutoCode catch-up) dispatch `bn:tags-changed`; the quote-card, transcript-page, and sidebar-assign write paths dispatch **nothing**. So any surface that renders the codebook must reconcile it against the store — `TagSidebar` does this with `mergePendingTags`, folding store-only tag names into the floor's `is_default` group. **The failure is invisible rather than loud:** `GET /codebook` emits `Uncategorised` unconditionally (`_get_or_create_uncategorised` + `_ensure_project_link` run on every GET), so a stale snapshot still renders the floor's card — just empty. It reads as "an empty group", not "a missing tag", which is why it survived to a user report. Don't fix this class by dispatching `bn:tags-changed` from `addTag`: four listeners refetch *all quotes* on that event and would fight the optimistic update. Reconcile against the store instead — no round trip to race, and it covers every write path rather than the one that remembered to fire an event
- **`codebook-changed` is the sibling event, and the v2 lens dispatched it NOWHERE — three of the four gaps were invisible because a neighbouring job fired it for them.** Five components refetch on it (`CodebookV2Sidebar`, `CodebookPanel`, `CodebookSidebar`, `LensSubtitleSync`, and the v2 lens itself); until 31 Aug 2026 every write path in `islands/CodebookV2.tsx` called its own private `reload()` and told none of them. **Only uninstall showed a symptom**, because it is the one write that starts no follow-on job: the row sat in the navigator until something unrelated reloaded it. Install was the identical bug wearing a disguise — the AutoCode job's `onComplete` in `AppLayout.tsx` dispatches `codebook-changed` when coding finishes, so the navigator *did* catch up, a job-length wait after the write, which reads as "slow" rather than "broken". Threshold apply moved `tentative_count` and left the pending badge (D10) on the old number; floor authoring changed the tag count `lensSubtitle.ts` renders. **Rule: whoever writes, announces — and announce INSTEAD of reloading, since the writing component listens too and doing both fetches twice.** One named `announce()` at `CodebookV2.tsx:307`, four call sites. **The generalisable tell: when one variant of an action is broken and its siblings look fine, suspect a neighbouring async job papering over them, not a bug unique to that variant.** The v1 lens carried the identical shape at `CodebookPanel.handleReportApply` and showed no symptom, because its sidebar rendered a status dot rather than a count (v1 was being retired as this landed)
- **`.bn-btn-sm` / `.bn-btn-lg` are SCOPED, so they silently do nothing outside `.v2-layout` / `.section-heading` / `.v2-nav` — no error, just the wrong size.** The size axis is deliberately not promoted to the shipped atom (`theme/organisms/codebook-v2.css` — *"a design-system decision nobody has taken"*), so the selectors name their scopes explicitly. Put `bn-btn bn-btn-secondary bn-btn-sm` on a button outside all three and it renders at full `.bn-btn` metrics, which is exactly what a size modifier failing open looks like: plausible, and wrong. This bit when Browse Library was added to the sidebar navigator — mounted by `AppLayout` in the left panel, a *sibling* of the lens, so inside neither existing scope; `.v2-nav` was added to that same rule rather than widening the atom. **When reusing a v2 button size on a new surface, check the surface is named in the rule** — and prefer naming it there over promoting the class, until someone takes the design-system decision. Corollary from the same change: reaching for a house class and then retuning its padding to fit (what `.sidebar-mini-btn` got first) is a bespoke control wearing a house name — find the existing vocabulary instead, `frontend/src` `className=` usage is the cheapest census of it
- **Hidden-group tag UX** — when a codebook group is eye-toggled off, TagInput autocomplete shows a grey closed-eye icon (`EyeClosedIcon`, 12px SVG, `.tag-suggest-hidden-icon` CSS class) next to suggestions from hidden groups. On accept, `handleTagAdd` in `QuoteGroup.tsx` calls `toggleTagGroupHidden()` to auto-unhide the group so the badge is immediately visible. `allTagNames` prop (all tags including hidden-group ones) feeds the TagInput exclude list, preventing invisible re-adds. `hiddenTagNames` (derived from `hiddenTagGroups` + `tagGroupMap`) flows through QuoteGroup → QuoteCard → TagInput as `hiddenTags` prop
- **Clickable cards must be `<a>` not `<div>`** — any card that navigates on click (stat cards, nav links, etc.) must use an `<a>` element with a real `href` so that Cmd+click opens in a new tab. Use `onClick` with `if (e.metaKey || e.ctrlKey || e.shiftKey) return; e.preventDefault();` to keep programmatic React Router navigation for normal clicks while letting modifier-key clicks fall through to native browser behaviour. `statTargetToHref()` in `Dashboard.tsx` converts `"tab:anchor"` targets to pathname URLs. CSS needs `text-decoration: none; color: inherit` to prevent link styling
- **React Router navigation + scroll** — calling `window.switchToTab("quotes")` then `window.scrollToAnchor("section-x")` works via backward-compat shims (`src/shims/navigation.ts`). The scroll uses retry-aware polling (50 × 100ms = 5s) because the destination page mounts and fetches data async. Anchor slugs must match between caller and target — AnalysisPage uses `toLowerCase().replace(/ /g, "-")` to match QuoteSections/QuoteThemes
- **Modal focus trapping via `useInert`** — `src/hooks/useInert.ts` sets `inert` on `#bn-app-root` while any portaled modal is open. Ref-counted (module-level counter) so overlapping modals don't remove `inert` prematurely. All 5 portal-based modals call `useInert(open)`: ModalNav (Help + Settings), ExportDialog, FeedbackModal, ThresholdReviewModal, AutoCodeReportModal. `resetInertCount()` exported for tests
- **Screen reader announcements** — `src/utils/announce.ts` provides `announce(message)` which sets text on a shared `aria-live="assertive"` region (`AnnounceRegion` component mounted in AppLayout). Used for star/hide/tag mutations (QuotesContext), tab navigation (AppLayout), and edit mode transitions (EditableText). Clears after 1s timeout. For tests: `resetAnnounce()` clears the module-level state
- **NavBar links are `<a>`, not `role="tab"`** — `NavLink` renders anchor elements. Tests use `getByRole("link", { name })` not `getByRole("tab", { name })`. The nav container is a plain `<nav>` (not `role="tablist"`). The native macOS toolbar uses tab semantics separately
- **Deriving a colour from light/dark in JS? Use `useIsDarkAppearance()` — `data-theme` alone is permanently light on the desktop.** The attribute is written in exactly four places, and **none of them fire in embedded mode**: `applyTheme` in SettingsModal/SettingsPanel (embedded intercepts the web Settings modal in favour of native Settings), the pre-paint boot script in `index.html` (reads `localStorage["bristlenose-appearance"]`, which only the web picker writes), and the dev PlaygroundStore. There is no server-side injection either. In the desktop app appearance is owned natively via `NSApp.appearance`, the WKWebView inherits it, and the report CSS follows `prefers-color-scheme` — a bridge channel for it was deliberately removed (see the comment in `BridgeHandler.swift`; don't re-add one). So `getAttribute("data-theme") === "dark"` reads `false` for ever on the Mac. `src/hooks/useIsDarkAppearance.ts` is the single answer: explicit `data-theme` wins when present (browser picker forcing a choice), else `matchMedia("(prefers-color-scheme: dark)")`, subscribing to **both** signals so a live switch repaints without a reload. **CSS is unaffected** — `light-dark()` and `prefers-color-scheme` rules were always correct on both surfaces; this is a JS-only trap, and it only bites code that computes a colour value (the analysis heatmap's OKLCH lightness band was pinned to light on every desktop report until 4 Aug 2026). It went unnoticed for so long because a full webview remount on every appearance switch masked the staleness; that remount was removed on 4 Aug. **Note `window.matchMedia` does not exist in jsdom at all** (like Web Storage — see `src/test-setup.ts`), so the hook guards for its absence and any test exercising the media-query path must install a mock. **`bristlenose/theme/js/analysis.js:289` carries the identical attribute-only read and is deliberately left alone** — it's the frozen vanilla JS of the sealed static render, which the desktop app never runs, so the bug is unreachable there and fixing it isn't a data-integrity fix. Don't "finish the job" by porting this fix into `theme/js/`

### Routing & serve mode

- **Health payload shape (Mar 2026)** — `GET /api/health` includes footer config: `links.github_issues_url` and `feedback.{enabled,url}` in addition to `status` and `version`. Reuse the shared `HealthResponse` type (`src/utils/health.ts`) instead of ad-hoc inline interfaces to avoid shape drift across `Footer`, `FeedbackModal`, About panel, and export embedded data
- **Route priority in `app.py`** — transcript file route (`GET /report/sessions/{filename}` with `transcript_*.html` filter) must be defined before the SPA catch-all (`GET /report/{path:path}`). Starlette resolves routes in registration order. The `/report` → `/report/` redirect is defined first, then transcript files, then the SPA catch-all, then the `StaticFiles` mount
- **`<!-- bn-app -->` markers** — wrap nav bar + all tab panels in `bristlenose/stages/s12_render/report.py`. The IIFE script block (including `BRISTLENOSE_ANALYSIS` JSON) is outside the markers and survives the serve-time substitution. `_REACT_APP_MOUNT` in `app.py` replaces these markers with `<div id="bn-app-root">`
- **IIFE-scoped globals need `window.` for React** — `bristlenose/stages/s12_render/report.py` wraps all JS in `(function() { ... })();`. Variables declared with `var` inside the IIFE are invisible to React (which runs in a separate ES module context). Any global that React needs must be explicitly assigned to `window.` inside the IIFE. Currently exposed: `window.BRISTLENOSE_VIDEO_MAP`, `window.BRISTLENOSE_PLAYER_URL`, `window.BRISTLENOSE_ANALYSIS`. If adding new globals for React, add `window.X = X;` after the `var` declaration — the `var` must stay for vanilla JS code in the same IIFE
- **Session route priority** — `/report/sessions/{filename}` handles both transcript HTML files (`transcript_*.html`) and React Router SPA routes (e.g. `/report/sessions/s1`). Non-transcript filenames serve the SPA HTML instead of raising 404, so React Router can handle client-side routing

### Video player

- **Two data paths** — video playback has two independent data flows: (1) **Static render path** — `html_helpers._build_video_map()` reads `InputSession.files` (full absolute paths) and writes `window.BRISTLENOSE_VIDEO_MAP` with correct `file://` URIs into the IIFE. `player.js` reads this via event delegation. (2) **Serve/SPA path** — the importer reads transcript headers (`# Source: interviews/show and tell 40.mov`) which store **relative paths including subdirectory** (written by `merge_transcript.py` using `fpath.relative_to(input_dir)`), stores them in the DB, and the video-map API (`/api/projects/{id}/video-map`) converts DB paths to `/media/` URIs via `_file_to_media_uri()`. `PlayerContext.tsx` fetches this API. **Encoding rule**: `_file_to_media_uri()` returns **unencoded** paths (e.g. `/media/interviews/show and tell 40.mov`). JavaScript's `encodeURIComponent()` in `PlayerContext.tsx` handles encoding once when building the player URL hash. Never add `urllib.parse.quote()` in Python — that causes double-encoding (`%20` → `%2520`). In SPA mode, `player.js` bails out (`if (document.getElementById('bn-app-root')) return`) — only `PlayerContext` handles playback
- **Glow index keying: session ID vs speaker code** — transcript segments have `data-participant` set to the speaker code (`m1`, `p1`), but the popout player sends `pid=sessionId` (`s1`) in `bristlenose-timeupdate` messages (because `TimecodeLink` passes `data.session_id` to `seekTo`). `buildGlowIndex` in `PlayerContext.tsx` extracts the session ID from the URL pathname (`/report/sessions/:sessionId`) and keys all transcript segment entries under that ID. Without this, the glow index would be keyed by speaker code and no entries would match the player's session-ID-based lookup
- **Progress bar on transcript segments** — `PlayerContext.tsx` sets a `--bn-segment-progress` CSS custom property (0–1) on the active `.transcript-segment` during playback. The CSS `::before` pseudo-element in `timecode.css` renders a 3px left border that fills top-to-bottom via `scaleY()`. The segment needs `position: relative` and `overflow: hidden` for this to work. `prefers-reduced-motion` disables the transition

### Data pipeline integration

- **Tag provenance** (`QuoteTag.source` column) — `"human"` for manually-added tags, `"autocode"` for LLM-suggested-then-accepted tags. Preserved across `put_tags` bulk-replace (snapshot before delete, restore on re-insert in `routes/data.py`). Exposed in quotes API as `source` on `TagResponse`. Not yet surfaced in UX — data laid down for future signal weighting. Migration in `db.py` adds column to existing databases
- **Word-level timing data** — Whisper captures per-word timestamps (`Word` model: `text`, `start_time`, `end_time`, `confidence`). The serve-mode importer populates `TranscriptSegment.words_json` — a TEXT column storing compact JSON (`[{"t":"word","s":0.5,"e":0.8},...]`). The transcript API exposes this as `words: [{text, start, end}, ...] | null` on each segment. VTT/SRT-only sessions have `words: null`. **Frontend consumption not yet implemented** — the API serves the data but `TranscriptPage.tsx` doesn't render word spans yet
- **Speaker role: the moderator's stored role is `"researcher"`, never `"moderator"`.** The `SpeakerRole` enum (`bristlenose/models.py`) is `researcher`/`participant`/`observer`/`unknown`; `"moderator"` is a display word only, never a stored/returned value. So `sp.role === "moderator"` is dead code that silently never fires on real data. Detect moderators by the badge **code prefix** (`sp.speaker_code.startsWith("m")`) — the robust convention used across `TranscriptPage.tsx`, `SessionsTable.tsx`, and `SessionsSidebar.tsx`. A test fixture hardcoding `role: "moderator"` will mask the bug (it did, until `ae522367`) — real-data-shaped fixtures use `"researcher"`

### Testing

- **Module-level stores persist across tests** — always call `resetStore()` / `resetSidebarStore()` / `resetPlaygroundStore()` / `resetActivityStore()` in `beforeEach`
- **An active `/new-branch` worktree contaminates `vitest` discovery — pass `--exclude '**/.claude/**'`.** Worktrees live at `.claude/worktrees/<name>/`, *inside* the main repo tree, and each carries a full `frontend/src/**/*.test.tsx` copy. `npx vitest run src/components/Foo.test.tsx` from the main `frontend/` also matches the worktree's `…/.claude/worktrees/*/frontend/src/components/Foo.test.tsx`; that copy has no `node_modules`, so it fails `Cannot find package '@testing-library/react'` — **and the failed-suite import breaks the jsdom environment for the *whole* run**, so every other file then dies with `ReferenceError: document is not defined` (looks like your change nuked the DOM; it didn't). Symptom seen 26 Jul 2026 with a concurrent codebook worktree present: 27/27 SidebarLayout tests "failed", all green again under `npx vitest run --exclude '**/.claude/**' <path>`. Proper fix is an `exclude: ['**/.claude/**']` entry in `vitest.config.ts` (the config doesn't exclude it today); until then, add the flag when a worktree is live (`git worktree list`).
- **`vi.mock` factory functions can't reference variables declared after them** (mocks are hoisted) — inline data directly
- **`useRef<T>()` needs explicit `undefined` argument** in newer TypeScript: `useRef<T>(undefined)`
- **Mock `getCodebook`** with `.mockResolvedValue()` in `beforeEach`, not just in `vi.mock` factory (`restoreAllMocks` resets it)
- **Router tests**: use `createMemoryRouter` with `routes` array (exported from `router.tsx`). Use `getByRole("link", { name })` not `getByText` to find NavBar links (they're `<a>` elements, not tabs)
- **Adding a router hook (`useNavigate`/`useLocation`) to an island whose `*.test.tsx` renders it bare throws** — most island tests do `render(<SomeIsland .../>)` with no Router provider (the island mounts standalone in production too). The moment the island calls `useNavigate` internally, every bare test throws "useNavigate() may be used only in the context of a &lt;Router&gt;". Fix without editing every call site: alias the render helper once at the top of the test file — `const render = (ui) => rtlRender(ui, { wrapper: MemoryRouter })` (see `SessionsTable.test.tsx`). Don't wrap each `render()` individually
- **`RouterProvider` does NOT render `children` — a `renderHook` wrapper that nests them inside it silently never runs the hook callback.** `wrapper: ({children}) => createElement(RouterProvider, {router}, children)` reads correctly and type-checks, but RouterProvider renders only its matched route tree, so the callback never fires and `result.current` stays `null` forever — no assertion on it can fail in a way that tells you why. The workaround this grows is worse than the bug: `useKeyboardShortcuts.test.ts` had a *second* `renderHook` over the **same router** "for the actual component tree", which mounted the route element **twice**. Two mounts = the hook's `document` keydown listener installed twice, so every bare-key handler ran twice per dispatch — a toggle always flipped back, making post-keypress state unobservable (tests could only assert `defaultPrevented`, never the resulting state). The returned `unmount` also tore down only the *second* tree, leaving a live listener firing after the test believed it had unmounted, until testing-library's global `cleanup`. **Fix: one `renderHook` whose wrapper renders the router and the children as _siblings_ under a `Fragment`** — `createElement(Fragment, null, createElement(RouterProvider, {router}), children)`. Module-level-store hooks (`useQuotesStore`) need no provider, so sibling placement is all they require. **Tells:** `result.current === null` from a store hook that always returns an object; or a NOTE in a test file explaining that state "can't be asserted here". **Diagnosing a double-mount:** keys gated on per-tree React context (`focusedId`/`selectedIds`) do NOT double-fire — each tree has its own provider and only one is reachable through the captured ctx, so the other bails at the guard. Only handlers reading *module-level* stores (FocusModeStore, SidebarStore) double-fire, which is why the symptom looks arbitrary (fixed 3 Aug 2026)
- **Playwright E2E tests** (`e2e/`) — 3 test layers (console errors, link crawler, network assertions) running against the smoke-test fixture on Chromium + WebKit. `playwright.config.ts` auto-starts `bristlenose serve` via `webServer` — locally uses `.venv/bin/bristlenose` (resolved path), in CI uses bare `bristlenose` (on PATH). Port 8150, overridable via `BN_E2E_PORT`. The link crawler skips `<a role="button">` elements. Known bugs are `test.fixme()` stubs. See `docs/design-playwright-testing.md`
- **`vi.useFakeTimers()` + `requestAnimationFrame` mocking** — fake timers replace `globalThis.requestAnimationFrame` / `cancelAnimationFrame`. If a hook uses `window.requestAnimationFrame` (not bare `requestAnimationFrame`), mocks must be installed on `window` too. Use the `installRafMock()` helper pattern: call it AFTER `vi.useFakeTimers()` to re-install synchronous rAF/cAF on both `globalThis` and `window`. React's passive effect cleanup runs after test teardown, so `window.cancelAnimationFrame` may be gone by then — the hook must guard: `if (typeof window.cancelAnimationFrame === "function")`. See `useScrollSpy.test.ts` for the canonical example
- **Safari `getBoundingClientRect()` during smooth scroll** — Safari returns physically impossible values (bottom < top, negative height) from `getBoundingClientRect()` while `scrollIntoView({ behavior: "smooth" })` animation is in progress. Don't trust `getBoundingClientRect()` for at least 600ms after triggering a smooth scroll. The `useScrollSpy` two-phase override is the canonical workaround. **A zero-size guard does NOT catch this** — a glitched rect keeps a plausible width, so an `x` derived from it survives while `y` is garbage. If you filter rects for usability, filter `width < 0 || height < 0` as well as `width === 0 && height === 0`; the two mean different things ("unusable measurement" vs "not laid out"). See `readCardRects` in `src/utils/spatialNav.ts`
- **jsdom reports EVERY `getBoundingClientRect()` as all-zero — so a geometry test that doesn't stub rects silently exercises the fallback path and passes for the wrong reason.** This is the same family as the missing `matchMedia`/Web Storage, but nastier, because there's no `undefined` to throw: you get a valid-looking `DOMRect` full of zeros, every element sits at the origin, and any "nearest element" search returns *something*. Two `useKeyboardShortcuts` tests named "ArrowDown works like j" passed for months this way — they were asserting the DOM-order fallback while claiming to test geometry, and only broke once the fallback itself was corrected. **Tell:** a geometric assertion that passes without the test ever having positioned anything. **Fix:** stub `el.getBoundingClientRect` per element (and `el.scrollIntoView`, also unimplemented) — see the `layout()` helper in `useKeyboardShortcuts.test.ts`. Also assert the *positive* case somewhere: a rect-reading helper whose only test is `expect(read([...])).toEqual([])` would still pass if it returned `[]` unconditionally, and "measures nothing" is exactly the failure that makes a geometric feature silently inert
- **Testing-library's cleanup does not remove a node the component appended to `document.body` — so a drag ghost outlives the test that made it, and `getByText` then finds two.** `TagRow`'s drag-start (`components/CodebookAuthoring.tsx`) clones the badge into `document.body` as `.drag-ghost` and removes it on the next animation frame, which is what gives a dragged badge its own shape under the cursor instead of dragging the whole row. RTL unmounts *its container*, not a sibling of it, and the rAF may not have fired before the next assertion — so any query after a `fireEvent.dragStart` can match the ghost as well as the live element, and the failure (`Found multiple elements with the text: X`) points at the query rather than at the drag two lines above. **Fix: filter ghosts when querying** — `screen.getAllByText(name).filter(el => !el.closest('.drag-ghost'))`, asserting exactly one survivor, as `live()` does in `CodebookAuthoringParity.test.tsx`. **Do NOT sweep them in `afterEach`:** removing the clone first makes the component's own `document.body.removeChild(ghost)` throw `NotFoundError` out of a rAF callback nothing awaits, which Vitest reports as unhandled errors on a suite that otherwise passes. Generalises to portals, toasts, and anything else rendered outside the RTL container whose teardown is asynchronous
- **A React `onKeyDown` that calls `preventDefault()` without `stopPropagation()` still reaches document-level listeners — check `e.defaultPrevented` before claiming a key.** `preventDefault` suppresses the browser's *default action*; it does not stop propagation, and a document-level `keydown` handler runs regardless. So a focused control that already handled a key (the sidebar resize separator, `role="separator"`, handles `←`/`→` in `useDragResize`) and a global shortcut bound to the same key both fire: one keypress resized the sidebar *and* moved the quote cursor *and* scrolled the page. `isEditing()` doesn't help — a `<div role="separator">` is not an input. Guard the specific key block with `if (e.defaultPrevented) return;`, **not** the top of the handler: hoisting it silently changes the Escape cascade and the ⌘A/⌘C traps too

### Sidebar & playground

- **Sidebar layout** — 6-column CSS grid (`SidebarLayout.tsx`): `[toc-rail | toc-sidebar | center | minimap | tag-sidebar | tag-rail]`. Minimap is column 4 (between center and tags) so it stays in place whether the tag sidebar is open or closed. TOC overlay (hover intent + direction-aware close via `useTocOverlay.ts`), drag-to-resize (`useDragResize.ts`), rail drag-to-open. `hoverDelay` and `leaveGrace` are JS-only values passed as props through `SidebarLayout` → `useTocOverlay`; the remaining sidebar layout values are CSS custom properties
- **Desktop embedded: rails removed** — when `isEmbedded()`, `SidebarLayout` adds the `embedded` class, gates out both close-× buttons, and redirects focus-on-close to `.center` (the hidden rail button can't take focus; `.center` gets `tabIndex={-1}` in embedded only). CSS `.layout.embedded { --bn-rail-width: 0 }` collapses every rail track in one token + `display:none` on the rail divs kills the phantom 1px border; the right gutter is restored to a symmetric inset on minimap-less tabs. Sidebars are toggled from the native toolbar (`toggleLeftPanel`/`toggleRightPanel`, already wired) + `[`/`]` keys; overlay/hover-peek mode is unreachable (rail-only trigger), so embedded TOC is closed↔push only. Browser keeps all rails/close-×. **Sessions-lens exception (14 Aug 2026):** embedded Sessions has NO web left panel — the native switcher popover replaced it; `AppLayout` gates `showSidebar`/`leftPanel`/`panel-state` and `useKeyboardShortcuts` gates `[` off the embedded sessions route (`embeddedSessionsPanelRemoved`), and the sticky-header session `Selector` collapses to its label. Browser Sessions unchanged. See `docs/design-sessions-popover-navigation.md`. Otherwise: `docs/design-sidebar.md` § Desktop embedded mode + `docs/mockups/mockup-desktop-rail-removal.html`
- **Rail drag-to-open** — dragging from the closed rail reveals the sidebar as a fixed overlay that tracks the pointer 1:1. On `pointerup`: width ≥ 60px commits to push mode (clamped to minWidth); below 60px aborts (snaps closed). The `toc-rail-dragging` / `tags-rail-dragging` CSS class is deferred to the first `pointermove` (not `pointerdown`) to prevent a ghost border flash before the user moves. `body.dragging` is added on `pointerdown` to disable text selection immediately
- **Drag handle safe zone** — the `useTocOverlay` hover intent timer is cancelled when the mouse enters the `.drag-handle` area, preventing the overlay from pre-empting a drag gesture. `onDragHandleMouseEnter` cancels the timer; `onDragHandleMouseLeave` restarts it. Rail area clicks on `.drag-handle` elements are also excluded from the "click anywhere in rail → overlay" behaviour
- **Scroll spy click intent override** — `useScrollSpy` has a two-phase click override via an optional `clickedIdRef` (set by TocSidebar on link click). **Phase 1 — immune (0–600ms)**: the clicked heading wins unconditionally, ignoring `getBoundingClientRect()` — this covers the smooth scroll animation where Safari returns glitched values (bottom < top, negative height). **Phase 2 — sticky (>600ms)**: the override holds as long as the standard scroll-position algorithm picks a heading within 1 index of the clicked heading. Clears when the user scrolls far enough that the gap exceeds 1. This fixes the last-heading highlight bug where Safari's `getBoundingClientRect()` returns impossible values during `scrollIntoView({ behavior: "smooth" })` animation
- **Overlay auto-close toggle** — `TocSidebar` reads `pg.overlayAutoClose` from PlaygroundStore. Default `false` (overlay stays open after clicking a TOC link — user closes by mousing out). When `true`, the panel closes after 400ms (legacy behaviour). Configurable via the dev playground
- **Responsive playground** — dev-only (`ResponsivePlayground.tsx`, `PlaygroundStore.ts`) injects CSS token overrides via `<style id="bn-playground-overrides">`. `PlaygroundStore` uses `useSyncExternalStore` + `sessionStorage` (not localStorage — resets on tab close). Code-split — only loaded when `--dev` flag is set (`AppLayout.tsx` dynamic import). The `PlaygroundFab` renders a floating button via `createPortal` to `document.body`. Playground controls include: animation speed scaler, overlay shadow (X offset, blur, opacity), auto-close toggle, and layout column debug overlay (colour-coded grid columns with labels)
- **`useDragResize` custom bounds** — accepts optional `minWidth` / `maxWidth` props (default 200/320). Used by keyboard resize (arrow keys ±10px, Home/End for min/max) and pointer drag (clamp during move, clamp on rail commit). Rail drag commit clamps to `minWidth` when the user releases below it but above the snap threshold (60px)
- **CodebookSidebar** — left sidebar for the Codebook tab (`CodebookSidebar.tsx`). Three sections: "Your tags" (project name), "Built-in" (Bristlenose-authored templates where `author === ""`), "Frameworks" (third-party templates where `author !== ""`). One `.toc-link` per codebook, not per group. Imported codebooks scroll to `#codebook-fw-{id}` anchors on CodebookPanel; not-imported codebooks dispatch `bn:codebook-browse` CustomEvent on `window` to open the browse modal (CodebookPanel listens). "Browse codebooks →" mini button dispatches the same event without a template ID. Active state is "last clicked" (`useState`), not scroll spy — CodebookPanel uses a horizontal grid. Data refresh: listens to `window "codebook-changed"` event. Keyboard `[` works on `/report/codebook`. CSS: `.toc-link.not-imported` (muted, accent hover) and `.sidebar-mini-btn` in `sidebar.css`
- **Inspector panel** — DevTools-style collapsible bottom panel in Analysis tab (`InspectorPanel.tsx`). `InspectorStore.ts` (module-level store) owns panel state: open/collapsed, height, selected source tab. `useVerticalDragResize.ts` handles pointer-based vertical resize with 3px motion threshold; drag-from-collapsed grows from 28px handle bar. Signal card selection (`.bn-selected` blue wash) syncs with inspector source tabs. `m` keyboard shortcut toggles the panel (route-guarded to analysis). Footer auto-hides when inspector is open. CSS in `inspector.css` (organisms)
