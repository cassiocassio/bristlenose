# channel-scenarios.txt — the fault-injection corpus for follower channels and
# after-<channel>/<version> holds. Run by scripts/test-channel-scenarios.sh.
#
# WHY A CORPUS
#
# The release machine talks to systems whose contracts are undocumented and
# change without notice (docs/design-release-principles.md, "Formalisms worth
# the effort"). It cannot be proved correct, so it is fed unlikely-but-possible
# worlds, and each one records what the RIGHT answer is. When a new way for the
# world to be weird turns up, in a release or in a review, it becomes a block
# here. That is the whole maintenance model.
#
# FORMAT — blocks separated by blank lines, key=value, # comments.
#
#   id=            unique; a known issue's id is the prefix by convention
#   about=         one line: the world this scenario builds
#   version=       the version verify probes (default 0.36.0)
#
#   The world, as winget-pkgs shows it to `gh`:
#   served=        version folders under manifests/…, space-separated;
#                  or 404 (none yet) · 403 (rate limit) · FAIL · HANG · SLOW:<s>:<folders>
#   prs=           open PRs: <version>@<age-hours>[,…]; none · FAIL · HANG
#                  age may be negative (the local clock behind GitHub's)
#   title=         PR title template, {v} for the version
#                  (default "Add version: Bristlenose.Bristlenose version {v}")
#   flip_after=N   after N gh calls the world becomes served_after / prs_after:
#                  something happened BETWEEN two reads
#   publish=       failed: the merge went in, Microsoft's publish pipeline did not
#   budget=        WINGET_BUDGET_HOURS in the sandbox conf (default 72)
#
#   Holds, as branches:
#   holds=         after-* branches in this repo (space-separated)
#   site_holds=    after-* branches in the website repo
#   landed=        holds whose commit is already on main
#   results=       skip the probes; feed release.sh this results file instead,
#                  lines `kind:a:b` joined by spaces (verdict:pypi:ok served:winget:0.36.1)
#
#   What correct looks like:
#   expect.winget=     the follower's verdict
#   expect.exit=       verify's exit code
#   expect.hold.<b>=   land · wait · unknown · badname · landed
#   expect.seconds=    verify must finish inside this (default 30)
#   expect.out=        a substring the output must contain
#
#   known=<ISSUE>      the code is known to get this wrong today; the issue is
#                      written up in docs/design-channel-version-lag.md §7.
#                      Reported KNOWN, not FAIL. When the code starts getting it
#                      right the runner FAILS until this line is removed, so a
#                      fix cannot land without retiring its scenario's tag.
